SECTION 5: PERIOD-LEVEL MATCHING
======================================================================

Scope: 36 companies with both a canonical run and financial_periods rows.
Company 76 (canonical-only) is excluded; it is reported at 1.2.

Canonical side: latest run per company only (same CTE as sections 1-3).
Expected 335 periods: 175 income, 160 balance.
Live side: financial_periods joined to income_statements (187 rows) and
balance_sheets (169 rows) for these 36 companies. Total: 356 live rows.

Span derivation on live side uses financial_periods.is_full_year (PARENT),
not income_statements.is_full_year (CHILD). Span is a property of the period.
The parent-child disagreement is already reported at 3.2 and is not conflated here.
Rules in order: months_covered=12 → full_year; months_covered IS NOT NULL AND !=12
→ part_year; months_covered IS NULL AND is_full_year=true → full_year;
months_covered IS NULL AND is_full_year=false → part_year.
The live side can never produce span = 'unknown'. Canonical can.
That asymmetry is a finding, not a bug.

Primary join key: target_company_id + fiscal_year + statement_type.
Span is NOT part of the primary join key. It is used only as a discriminator
when the primary key yields more than one live row, or when multiple canonical
periods share a group and compete for the same live rows (see rules below).
The match is INJECTIVE: a live row may be claimed by at most one canonical period.
Span is compared as a field and reported at 5.4.
period_end is compared as a field (5.5), NOT used as a join key (see 3.1).

Matching rules per canonical period in a group (company+fiscal_year+statement_type):
  Single canonical in group:
    1. No live rows → bucket c.
    2. Exactly one live row → bucket a, matched.
    3. Multiple live rows, canonical span known AND exactly one matches → bucket a.
    4. Otherwise → bucket b, ambiguous.
  Multiple canonicals in group (competition for live rows):
    5. If this canonical's span matches live rows AND it is the only canonical
       with that span match → WINNER → bucket a.
    6. If another canonical wins (rule 5 applies to a peer, not to this period)
       → bucket e (live row claimed by a closer span match).
    7. Otherwise → bucket b, ambiguous.

SECTION 7: SCOPE AND LIMITS
======================================================================

Figure-level value comparison is in SECTION 6 above.

The primary join key used in Section 6:
  target_company_id + fiscal_year + statement_type
Span is used only as a discriminator. Bucket-b (ambiguous) and bucket-e
(displaced by injective resolution) periods are excluded from figure comparison.

period_end is deliberately compared rather than joined on, for the reason
given in 3.1: a fabricated Dec-31 date on the live side may disagree with
the canonical period_end derived from evidence, and that disagreement is
itself a finding, not a key collision to be silently resolved.
