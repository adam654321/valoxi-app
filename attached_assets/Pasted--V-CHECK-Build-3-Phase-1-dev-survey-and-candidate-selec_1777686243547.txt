QUERIES TO RUN

1) All chase-up schedules with token state, including finalDeadlineDate:

SELECT
  cs.id AS schedule_id,
  cs.portal_token_id,
  cs.target_company_id,
  cs.submission_deadline,
  CURRENT_DATE - cs.submission_deadline AS days_overdue,
  cs.is_active,
  cs.is_completed,
  cs.completion_reason,
  cs.manual_deadline_delay_days,
  pat.chase_up_status,
  pat.escalation_level,
  pat.chase_email_count,
  pat.final_deadline_date
FROM chase_up_schedules cs
INNER JOIN portal_access_tokens pat ON cs.portal_token_id = pat.id
ORDER BY cs.id;

2) Confirm zero requirement rows for the candidate target companies (so Rule B does not interfere with Rule D V-checks):

SELECT cdr.target_company_id, COUNT(*) AS row_count
FROM company_document_requirements cdr
WHERE cdr.target_company_id IN (
  SELECT DISTINCT cs.target_company_id
  FROM chase_up_schedules cs
  WHERE cs.is_active = true AND cs.is_completed = false
)
GROUP BY cdr.target_company_id
ORDER BY cdr.target_company_id;

3) Confirm chase_up_emails state for tokens we may select (so we can predict ladder behaviour if Rule D were to NOT fire on any case):

SELECT portal_token_id, email_sequence_number, email_type, delivery_status
FROM chase_up_emails
WHERE portal_token_id IN (
  SELECT cs.portal_token_id
  FROM chase_up_schedules cs
  WHERE cs.is_active = true AND cs.is_completed = false
)
ORDER BY portal_token_id, email_sequence_number;
