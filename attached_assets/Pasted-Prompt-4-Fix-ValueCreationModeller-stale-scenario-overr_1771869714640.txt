I need to fix a stale state bug in client/src/components/target-company/ValueCreationModeller.tsx. When the user edits assumptions in one scenario (e.g. bear), switches to another scenario tab (e.g. base), then switches back to bear, the localAssumptionOverrides and localExitOverrides state can hold stale values from the previous editing session that don't match what's now been saved to the server. This causes a mismatch between what's displayed in the AssumptionsPanel and what's being used for calculations in the parent.
Context: We've just fixed the input handling in AssumptionsPanel (Prompt 3), ValuationSection (Prompt 1), and ViabilitySection (Prompt 2). This is the final fix — cleaning up the parent orchestrator so scenario switches don't carry stale local overrides.
Bug: localAssumptionOverrides and localExitOverrides persist across scenario tab switches
The localAssumptionOverrides state is keyed by assumption row ID. When the user switches from bear to base, the base scenario has completely different assumption row IDs, so the old bear overrides don't match any base rows — they're just ignored. But when switching back to bear, the old bear row IDs ARE still in localAssumptionOverrides, and those stale values get used for calculations even though the server may now have newer saved values.
Similarly, localExitOverrides persists across scenario switches even though exit assumptions may differ per scenario context.
Fix 1: Clear local overrides when activeScenarioType changes:
Add this useEffect:
jsuseEffect(() => {
  setLocalAssumptionOverrides(null);
  setLocalExitOverrides(null);
}, [activeScenarioType]);
Place it after the existing state declarations for localAssumptionOverrides and localExitOverrides.
Fix 2: Also clear local overrides when selectedModelId changes:
If the user switches to a different deal model, all local overrides are stale.
Add or extend the effect:
jsuseEffect(() => {
  setLocalAssumptionOverrides(null);
  setLocalExitOverrides(null);
}, [activeScenarioType, selectedModelId]);
Fix 3: Clear local overrides when scenario mode changes (linked ↔ custom):
When switching from custom to linked mode, activeScenarioType is forced to 'base' (this already happens in handleModeChange). But if the user was already on 'base' in custom mode and switches to linked mode, the activeScenarioType doesn't change, so the useEffect from Fix 1 won't fire. The overrides should still be cleared because linked mode derives scenarios differently.
Fix: Also clear in the handleModeChange callback:
jsconst handleModeChange = useCallback((mode: 'linked' | 'custom') => {
  updateModeMutation.mutate({ scenarioMode: mode });
  if (mode === 'linked') {
    setActiveScenarioType('base');
  }
  setLocalAssumptionOverrides(null);
  setLocalExitOverrides(null);
}, [updateModeMutation]);
Do NOT change:

The handleLocalAssumptionChange or handleLocalExitChange callbacks
The calculation useMemos (projections, returnMetrics, scenarioComparison, etc.)
The AssumptionsPanel props or rendering
The tab layout or UI structure
Any query keys or data fetching

After making changes, verify:

Edit revenue growth in base scenario, switch to bear tab, switch back to base — the value should reflect what was saved, not the stale local override
Switch between linked and custom mode — no stale values carry over
Switch between different deal models — assumptions reset cleanly
Calculations (projections, IRR, MOIC) update correctly after switching scenarios
No TypeScript errors
