PROMPT 3 — Simplify deal_structure output schema in the prompt
The deal_structure prompt asks Gemini to return three complete structure objects each with six nested sub-objects. This is the root cause of the output token overflow. We need to simplify the schema while keeping all deal-critical information. In server/prompts/stage2-deal-structure-prompt.ts find the JSON schema example inside the prompt string — it shows the expected response shape with a structures array containing objects with consideration, seller_obligations, warranties_indemnities, completion_mechanism, effective_price, and other nested sub-objects. Replace the schema example with a simplified version. Each object in the structures array should now have these fields only: name as a string like Conservative Approach, strategy as a string description, consideration as an object keeping all its existing payment fields exactly as they are — upfront_cash, deferred, earnout_maximum, earnout_metric, earnout_period_months, retention_escrow, total_headline, upfront_percent, risk_to_buyer, suitable_when — these are the most important fields and must be preserved in full, key_conditions as an array of strings, risk_to_buyer as a string low medium or high, suitable_when as a string, and notes as a single string that summarises the key warranty terms non-compete obligations completion mechanism and any other deal protection terms in plain text rather than as nested objects. Remove the seller_obligations object, the warranties_indemnities object, the completion_mechanism object, and the effective_price object from the schema entirely — their content should be captured in the notes string instead. Update the instruction text in the prompt to tell Gemini to summarise warranty periods non-compete obligations and completion mechanics as plain text in the notes field rather than as structured sub-objects. Keep all top-level fields outside the structures array completely unchanged — recommended_structure, recommendation_rationale, negotiation_priorities, deal_breaker_terms, key_findings, narrative, score, confidence, expert, company_name, analysis_date must all remain exactly as they are. After the change confirm the structures array schema no longer contains seller_obligations, warranties_indemnities, completion_mechanism, or effective_price as nested objects, the consideration object still has all its payment fields, a notes string field is present in each structure, all top-level fields outside structures are unchanged, TS error count remains at 6, and only stage2-deal-structure-prompt.ts was modified.​​​​​​​​​​​​​​​​
