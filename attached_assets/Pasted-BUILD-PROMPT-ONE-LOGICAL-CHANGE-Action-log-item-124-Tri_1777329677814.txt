A3. Add the new fallback branch inside the for...of loop
Position: between the end of the existing stripeSubscriptionId block (currently line 186) and the billingService.expireTrial call (currently line 188).
The new branch:
if (!sub.stripeSubscriptionId && sub.stripeCustomerId) {
try {
const result = await stripe.subscriptions.list({
customer: sub.stripeCustomerId,
status: 'all',
limit: 10,
});
const liveStripeSub = result.data.find(
s => s.status === 'active' || s.status === 'trialing'
);
if (liveStripeSub) {
console.warn(
[billing-cron] Trial expiry skipped for company ${sub.userCompanyId}:  +
stripeSubscriptionId is NULL but found live Stripe sub ${liveStripeSub.id}  +
(status=${liveStripeSub.status}) via customer ${sub.stripeCustomerId}.  +
Will re-evaluate tomorrow.
);
continue;
}
} catch (stripeErr) {
console.error(
[billing-cron] Stripe lookup failed for company ${sub.userCompanyId}  +
(customerId=${sub.stripeCustomerId}), skipping cancel:,
stripeErr
);
continue;
}
}
If stripeCustomerId is also NULL, the if condition is false and execution falls through to the existing expireTrial call. No special handling needed.
If Stripe returns no live subs (the find returns undefined), we fall out of the if block and execution continues to the existing expireTrial call. Cancel proceeds normally.
