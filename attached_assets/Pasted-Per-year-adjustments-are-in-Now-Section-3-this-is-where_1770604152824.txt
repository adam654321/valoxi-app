Mutation:
One mutation that updates the deal model: PUT /api/v2/deal-models/${modelId} with partial model fields. This is used for all editable values in this section. On success, call onDataChange().
Important UX decision — debounced saves:
The user will be dragging sliders and typing into inputs. We don't want to fire an API call on every keystroke or slider tick. Use a debounce pattern:

Keep local state for all editable values (initialised from model props)
On change, update local state immediately (for instant visual feedback)
Run the calculation engine client-side with the local values (for instant number updates)
Debounce the API save — fire the PUT mutation 500-800ms after the last change
Show a subtle "Saving..." indicator when the debounce is pending, and "Saved" briefly when it completes
When new model data arrives from the server (after save), sync local state if it differs

This gives the user a responsive, slider-driven experience while keeping the server in sync.
