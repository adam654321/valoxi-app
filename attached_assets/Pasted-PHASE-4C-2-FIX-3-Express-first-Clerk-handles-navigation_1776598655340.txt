PHASE 4C-2 FIX 3 — Express first, Clerk handles navigation

PROBLEM FROM LAST TEST
Version 2 used signOut(callback, { redirectUrl }) — logout cleared cookies (proven by subsequent refresh) but the browser did not navigate. The combination of callback form and redirectUrl option is producing ambiguous behaviour in @clerk/react 6.4.2.

REVISED APPROACH
Per the authoritative Clerk docs (https://clerk.com/docs/react/reference/objects/clerk#sign-out), signOut's redirectUrl is "The full URL or path to navigate to after sign out is complete." Rather than rely on the callback + redirectUrl combo, we separate concerns:
1. Express logout runs FIRST so sid is destroyed with no dependency on Clerk behaviour.
2. Then signOut({ redirectUrl: "/sign-in" }) clears __session. Clerk navigates.
3. Dashboard "after sign-out" is already set to /sign-in, so even if the SDK version ignores the redirectUrl option, the destination is the same.

Acceptable tradeoff: if signOut throws between the Express POST and the navigation, __session remains client-side. However, this is extremely unlikely — signOut's cookie clear is client-side synchronous. And even if it happened, __session without Express session won't matter because we would surface it on the next navigation anyway.

STEP 1 — Modify client/src/components/layout/NavUser.tsx

Find the logoutMutation block. Find the current mutationFn:

    mutationFn: async () => {
      if (clerkEnabled) {
        // Callback form with explicit in-callback navigation.
        // Order inside callback: Express logout (clears sid), then navigate.
        // signOut() has already cleared __session before the callback runs.
        // We do NOT pass redirectUrl — @clerk/react ignores it when a callback
        // is present, which caused the previous iteration to hang on no-navigation.
        await signOut(async () => {
          await apiRequest("POST", "/api/v2/auth/logout");
          window.location.href = "/sign-in";
        });
        // Execution does not continue past signOut in practice because the
        // callback navigates, but leaving as-is for type correctness.
      } else {
        await apiRequest("POST", "/api/v2/auth/logout");
      }
    },

Replace with:

    mutationFn: async () => {
      // Express first: destroy sid server-side. Runs to completion before Clerk.
      await apiRequest("POST", "/api/v2/auth/logout");
      if (clerkEnabled) {
        // Clerk clears __session and navigates to /sign-in.
        // Dashboard "after sign-out" is also set to /sign-in as belt-and-braces
        // in case the SDK version does not honour this option.
        await signOut({ redirectUrl: "/sign-in" });
        // Navigation handled by Clerk. Code below does not execute in this path.
      }
    },

Also find the current onSuccess:

    onSuccess: () => {
      // Only reached in the flag-off path. Flag-on navigation is handled by Clerk.
      if (!clerkEnabled) {
        window.location.href = "/login";
      }
    },

Leave this unchanged. Same comment applies: flag-off path uses the fallback.

Rest of the component is untouched.
