We are fixing the HoT offline download failure. The error is that the HoT is being generated via the generic create-offline route which calls generateDocumentFile with an empty data context — so buildHoTHtml fails because transactionTypeLabel, offerPrice and all other deal-specific fields are undefined. The correct fix is to route the offline HoT download through createHoTFromAcceptedOffer which reads the accepted offer letter's frozen documentData. This is the same source the portal uses and ensures the HoT always reflects what was actually accepted not the current deal model state. portalTokenId is optional on createHoTFromAcceptedOffer so no portal is needed.
