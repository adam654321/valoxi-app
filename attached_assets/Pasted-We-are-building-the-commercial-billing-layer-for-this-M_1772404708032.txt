We are building the commercial billing layer for this M&A platform. This is Stage 1, Step 1: adding the subscription database schema.
Context:

The platform has four tiers: CORE, PROFESSIONAL, EXPERT, ENTERPRISE
Plus a free trial state, add-on company slot purchases, and per-seat billing
Billing is per tenant (user_companies table — one subscription per tenant)
The schema must support Stripe webhooks, admin overrides (comped access), 5D community discounts, and community free months
We use Drizzle ORM with PostgreSQL. Schema lives in shared/schema/. The barrel export is shared/schema/index.ts which is re-exported by shared/schema.ts. Drizzle config points at shared/schema.ts.

What to build:
Create a new file shared/schema/billing.ts with the following:
Three Postgres enums:

plan_key: values CORE, PROFESSIONAL, EXPERT, ENTERPRISE
subscription_status: values active, trialing, past_due, canceled, incomplete, admin_comped
billing_interval: values month, year

Table 1: subscriptions
One row per tenant. Columns:

id serial PK
user_company_id integer, NOT NULL, UNIQUE, FK → user_companies.id
stripe_customer_id varchar(255), nullable
stripe_subscription_id varchar(255), unique, nullable
plan_key enum, NOT NULL, default CORE
status enum, NOT NULL, default trialing
billing_interval enum, default month
current_period_start timestamp, nullable
current_period_end timestamp, nullable
trial_start timestamp, nullable
trial_end timestamp, nullable
cancel_at_period_end boolean, NOT NULL, default false
add_on_company_slots integer, NOT NULL, default 0
additional_seats integer, NOT NULL, default 0
is_community_member boolean, NOT NULL, default false
community_free_months_remaining integer, NOT NULL, default 0
enterprise_overrides jsonb, nullable
admin_notes text, nullable
created_at timestamp, defaultNow, NOT NULL
updated_at timestamp, defaultNow, NOT NULL

Table 2: subscription_events
Immutable append-only audit log. Columns:

id serial PK
user_company_id integer, NOT NULL, FK → user_companies.id
stripe_event_id varchar(255), unique, nullable (null for admin-generated events)
event_type varchar(100), NOT NULL
previous_status subscription_status enum, nullable
previous_plan_key plan_key enum, nullable
new_status subscription_status enum, nullable
new_plan_key plan_key enum, nullable
payload jsonb, NOT NULL, default {}
admin_user_id integer, nullable
processed_at timestamp, defaultNow, NOT NULL

Table 3: addon_purchases
Purchase history for add-on slots and seats. Columns:

id serial PK
user_company_id integer, NOT NULL, FK → user_companies.id
addon_type varchar(50), NOT NULL (company_slot or seat)
quantity integer, NOT NULL, default 1
stripe_payment_ref varchar(255), nullable
unit_price_minor_unit integer, NOT NULL (price in pence/cents)
currency varchar(3), NOT NULL, default gbp
purchased_at timestamp, defaultNow, NOT NULL

Zod insert schemas using createInsertSchema (omitting id and auto timestamps) for all three tables.
TypeScript types — inferred select types and insert types for all three tables, plus plain union type exports:

PlanKey = 'CORE' | 'PROFESSIONAL' | 'EXPERT' | 'ENTERPRISE'
SubscriptionStatus = 'active' | 'trialing' | 'past_due' | 'canceled' | 'incomplete' | 'admin_comped'
BillingInterval = 'month' | 'year'

Wire it up:

Add export * from './billing'; to shared/schema/index.ts (before the core export)
In shared/schema/relations.ts:

Import subscriptions, subscriptionEvents, addonPurchases from ./billing
Update userCompaniesRelations to add: subscription (one → subscriptions), subscriptionEvents (many), addonPurchases (many)
Add three new relation exports: subscriptionsRelations, subscriptionEventsRelations, addonPurchasesRelations — each with a userCompany one-relation back to userCompanies



Do not run db:push yet. Schema only for now.
