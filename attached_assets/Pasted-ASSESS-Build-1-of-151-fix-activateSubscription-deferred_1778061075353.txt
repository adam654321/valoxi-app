Goal of this build: change activateSubscription() so that subscription
lifecycle events are written at the correct time. Specifically:

(a) The DB upsert in activateSubscription stays where it is (checkout
    time). No change to that block.
(b) The two lifecycle event writes (billingRepository.logEvent at
    line 162-176 and funnel track() at line 182) are REMOVED from
    activateSubscription.
(c) A new helper method confirmFirstPayment(userCompanyId, planKey,
    billingInterval, paidInvoiceId) is added. It checks
    subscription_events for any prior 'subscription.activated' row
    for this user_company_id. If none exists, it writes both events
    (logEvent + track) using 'subscription.activated' as the event
    type. If one exists, it does nothing. This makes the helper
    idempotent against duplicate first-payment webhooks.
(d) The line 172 hardcode `newStatus: 'active'` becomes redundant
    because the logEvent moves to confirmFirstPayment, but for the
    new write inside confirmFirstPayment, newStatus must reflect the
    actual subscription row status at the moment of first payment
    (which will be 'active' from Stripe's invoice.paid). For now we
    can read the subscription back via billingRepository.getByCompanyId
    and use subscription.status. This handles the case Replit flagged
    where Stripe reports trialing at checkout but invoice.paid lands
    later when status is active.
