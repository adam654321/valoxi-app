Read-only. Do not edit. Produce a verbatim change plan at the end.

Background
6D2 dunning lifecycle is shipped. Customers can now have payments fail and
be auto-cancelled cleanly. 6E gives them self-service control: update card,
view invoices, update billing address, cancel subscription. We use Stripe's
hosted Customer Portal so we don't build any of these UIs ourselves; we just
create portal sessions and redirect.

Locked design decisions
  (1) Stripe-hosted portal, not custom-built. Single Stripe Dashboard config,
      shared across dev and prod (one portal config per Stripe account).
  (2) Features enabled: update payment method, view invoices/receipts,
      update billing details (name, address, email), cancel subscription.
  (3) Cancel mode: cancel_at_period_end = true. Customer keeps access through
      the end of their current paid period, then customer.subscription.deleted
      fires when the period ends. Existing 6D2 webhook handler picks this up
      cleanly.
  (4) Plan switching DISABLED in portal. We have our own upgrade UI in
      client/src/pages/billing.tsx and the price logic is custom (5D coupon
      handling, addon billing, pro-rata credits via customer balance). Letting
      Stripe portal swap plans would bypass all that.
  (5) Cancellation reasons: enable Stripe's optional reason capture
      (declining quality, missing features, switched service, too expensive,
      too complex, low value, customer service, other). Stripe stores these
      on cancellation_details which we already read in the
      customer.subscription.deleted webhook payload, so we get them for free.
  (6) Branding: use Stripe portal's basic branding tab. Logo + colour. Match
      the Valoxi orange (#F97316 from frontend config). No custom CSS.
  (7) Default return URL after portal session: the Valoxi billing page
      (whatever path that currently is, likely /billing or /account).
