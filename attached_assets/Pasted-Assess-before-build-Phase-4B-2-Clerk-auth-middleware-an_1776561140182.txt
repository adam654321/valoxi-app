Assess before build. Phase 4B-2 Clerk auth middleware and dual-path isAuthenticated. Read-only validation. Do not modify any files, do not install packages.
Goal: add Clerk JWT verification alongside the existing session-based auth, gated behind a CLERK_ENABLED feature flag. When the flag is off (default), zero behavioural change. When on, isAuthenticated tries Clerk first and falls back to session. CSRF is skipped for Clerk-authenticated requests because JWT bearer tokens are their own anti-CSRF mechanism.
Proposed plan.
Step 1. Wire clerkMiddleware() globally in server/routes.ts.
Mount @clerk/express's clerkMiddleware() immediately after the session middleware and before attachCsrfToken. clerkMiddleware is always mounted (not gated on CLERK_ENABLED) because it is a no-op when no Authorization header or Clerk cookie is present. Its job is to populate req.auth so downstream code can read it via getAuth(req).
Proposed order in server/routes.ts registerRoutes:

app.set('trust proxy', 1)
app.use(createSessionMiddleware(pool))
app.use(clerkMiddleware()) — new
app.use(attachCsrfToken)
app.use('/api/', generalLimiter)
registerModularRoutes(app)

Step 2. Create server/middleware/clerk-auth.ts.
New file exporting a helper function tryClerkAuth(req) that:

Returns null if CLERK_ENABLED !== 'true'
Returns null if getAuth(req).userId is null (no token or invalid token)
Looks up the users table by clerkUserId = getAuth(req).userId
If a matching user is found and isActive, returns { localUserId, userCompanyId }
If no matching user is found (Clerk JWT valid but no DB row), returns { error: 'CLERK_USER_NOT_LINKED' } — the JIT rejection per the Phase 4B decision

Signature:
tryClerkAuth(req): Promise<{ localUserId: number; userCompanyId: number | null } | { error: 'CLERK_USER_NOT_LINKED' } | null>
Step 3. Modify server/middleware/auth.ts isAuthenticated.
Update isAuthenticated to be dual-path:

Call tryClerkAuth(req).
If result has { localUserId }: populate req.session.userId, req.session.userCompanyId, set (req as any).clerkAuthenticated = true, call next().
If result is { error: 'CLERK_USER_NOT_LINKED' }: return 403 with the error code and a clear message like "Account not provisioned. Contact support."
If result is null: fall through to the existing session-based check unchanged.

Do not modify isSystemAdmin, requirePermission, refreshSessionPermissions, or any other function in auth.ts. Only isAuthenticated changes.
Step 4. Modify server/middleware/csrf.ts validateCsrfToken.
Skip CSRF validation if (req as any).clerkAuthenticated === true. Add the check at the top of the function, after the GET/HEAD/OPTIONS shortcut. JWT bearer auth is itself anti-CSRF because JWTs are sent via Authorization header, not cookies, and cannot be forged cross-site by a browser.
Step 5. Type declaration additions.
Add TypeScript declarations so req.clerkAuthenticated is typed correctly. Either extend the Express Request interface via declaration merging in a .d.ts file, or use a dedicated interface. Report the cleanest approach given the existing type setup in the project.
Step 6. Verification.
a. TS check: expect 0 errors.
b. Server boot: expect clean boot with clerkMiddleware mounted. No Clerk-related warnings or errors.
c. CLERK_ENABLED=false (current default): verify existing session auth works. Log in as a kept user, hit /api/v2/auth/me, expect 200 with the user object.
d. CLERK_ENABLED=true, no Authorization header: hit /api/v2/auth/me with a valid session cookie but no Bearer token, expect 200 (tryClerkAuth returns null, falls through to session).
e. CLERK_ENABLED=true, no session cookie, no Authorization header: expect 401 (both paths fail).
No end-to-end Clerk JWT testing in this phase — deferred to 4B-3 or 4C when we have a way to obtain tokens.
