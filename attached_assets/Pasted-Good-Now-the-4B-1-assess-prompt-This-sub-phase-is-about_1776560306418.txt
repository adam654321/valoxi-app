Assess before build. Phase 4B-1 Clerk webhook plumbing. Read-only validation. Do not modify any files, do not install any packages, do not run any SQL.
Goal: add a Clerk webhook endpoint that verifies Svix signatures and logs events. No database writes, no auth changes. Just plumbing that can be tested end-to-end via Clerk Dashboard's "send test event" button before we build event handlers in Phase 4B-3.
Proposed plan.
Step 1. Install svix.
npm install svix
Svix is the webhook delivery provider Clerk uses. svix is the Node client library that verifies webhook signatures. Standard for Clerk integrations.
Step 2. Add raw body parser for /api/v2/webhooks/clerk in server/index.ts.
Svix signature verification requires the raw bytes of the request body. Currently server/index.ts line 15 does this for Stripe:
app.use('/api/v2/billing/webhook/stripe', express.raw({ type: 'application/json' }));
Add a mirror line immediately below it, before the express.json() call on line 16:
app.use('/api/v2/webhooks/clerk', express.raw({ type: 'application/json' }));
Step 3. Create server/routes/webhooks.routes.ts.
New file with a single POST handler at /clerk that:

Reads CLERK_WEBHOOK_SIGNING_SECRET from env.
Verifies the Svix signature using svix/Webhook class (pass headers svix-id, svix-timestamp, svix-signature).
On signature failure, returns 400 with an error message.
On success, parses the event body, logs [clerk-webhook] received <event_type> for user <user_id> (or equivalent), returns 200 with { received: true }.
No DB writes. No event handler dispatch yet. That is Phase 4B-3.

Step 4. Register the webhook route in server/routes/index.ts.
Add a line registering the new route. Register it WITHOUT any middleware (no isAuthenticated, no validateCsrfToken, no requireActiveSubscription). The endpoint is intentionally unauthenticated because Clerk is the caller and auth is via Svix signature. Place the registration alongside other public routes like app.use('/api/v2/billing', billingWebhookRoutes); for consistency.
Step 5. Verify the system.
Run npm run check (expect 0 errors) and restart the dev server (expect clean boot, no Clerk-related errors).
Step 6. Functional test (Adam does this via Clerk Dashboard).
In Clerk Dashboard under Webhooks, open the endpoint we configured earlier and click "Send test event" (or "Send Example"). Check Replit logs for the received event and 200 response.
