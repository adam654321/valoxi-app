Section 3 (Valuation & EV Bridge) has two issues to fix:
Issue 1: Input values jump when typing
When entering a number like 70000 into a bridge input, the value jumps back (e.g. to 70) partway through typing, then works on retry. This is caused by the debounced save — the mutation fires, the server responds, onDataChange() invalidates the query, fresh model data arrives, and the component syncs server values back into local state, overwriting what the user was still typing.
Fix: Add an "editing guard" pattern. The component should track whether the user is actively editing (has focus on an input). While any input is focused, do NOT sync incoming server/prop data into local state. Only sync when:

The component first mounts
The modelId changes (user switched models)
No input is currently focused (user has finished editing)

Implementation approach:

Add a useRef<boolean> called isEditing (or track which field is being edited)
On input onFocus, set the ref to true
On input onBlur, set the ref to false, and then sync from props if needed
In the useEffect that syncs model props → local state, check isEditing.current and skip the sync if true
The debounced save should still fire normally — it just shouldn't trigger a local state overwrite while focused

Alternatively, a simpler approach: don't call onDataChange() (which invalidates/refetches) from the debounced save mutation's onSuccess. Instead, just let the local state be the source of truth while editing. Only call onDataChange() on blur or when switching away from the section. The sticky banner already recalculates from local state client-side, so the user sees correct numbers immediately.
Pick whichever approach fits the current code structure better — the key requirement is: typing into an input must never be interrupted by incoming server data.
Issue 2: Text is too small in places
Review all text sizes in ValuationSection.tsx and bump up anything that's too small for comfortable reading:

Any text-xs in labels or values should generally be text-sm at minimum
Currency values in the bridge should be clearly readable — at least text-base or text-lg for the amounts
The EV formula display should be prominent — text-lg or larger
The Enterprise Value and Offer Price rows should be the most prominent — text-xl font-semibold or similar
Source labels like "From expert" badges can stay small (text-xs) since they're supplementary
The consideration structure preview at the bottom can be slightly smaller since it's informational, but still readable

General rule: if the user needs to read and act on a number, it should be at least text-sm / 14px. If it's a key financial figure, text-base to text-xl.
