# Prompt 4: Linked/Custom Scenario Mode (Bear/Base/Bull Range System)

## Context

This is the final prompt (4 of 4) in the Value Creation Modeller redesign. Prompts 1-3 are applied. The 5-tab architecture with dashboard and impact bar is live. This prompt replaces the opaque `revenueGrowthMultiplier` / `costPressureAdjustment` scenario system with an intuitive "range dial" that automatically derives Bear and Bull cases from the Base assumptions.

This is the deepest change — it touches the database schema, the calculation engine, the API, and the UI.

---

## Current Scenario System (What We're Replacing)

**Schema:** `valueCreationScenarios` table has:
- `scenarioType`: 'bear' | 'base' | 'bull'
- `revenueGrowthMultiplier`: decimal (e.g. 0.6 for bear, 1.0 for base, 1.4 for bull)
- `costPressureAdjustment`: decimal (e.g. 1.5 for bear, 0 for base, -0.5 for bull)

**Calculator:** `calculateScenarios()` takes `ScenarioMultipliers` and applies them:
- `effectiveRevenueGrowth = baseGrowth × revenueGrowthMultiplier`
- `effectiveCostGrowth = baseCostGrowth + costPressureAdjustment`

**Problems:**
- "0.6x revenue growth multiplier" is meaningless to users
- Bear/Base/Bull use entirely separate assumption sets with no visible relationship
- No way to intuitively adjust the range between scenarios
- Changing base assumptions requires manually recalibrating bear and bull

---

## New Scenario System: Linked + Custom Modes

### Concept

**Linked mode (default):** User sets Base assumptions directly. Then sets a "range" (in percentage points). Bear and Bull are automatically derived:

```
Bear revenue growth = Base revenue growth − range
Bull revenue growth = Base revenue growth + range
```

Example: Base = 5% growth, Range = 10pp
→ Bear = −5% growth, Base = 5%, Bull = 15%

Cost adjustments are derived automatically at sensible ratios (not user-configurable in Linked mode):
- Bear: CoS grows faster (+ range × 0.5), overheads slightly higher (+ range × 0.2)
- Bull: CoS grows slower (− range × 0.5), overheads slightly lower (− range × 0.2)
- Exit multiple also flexes: Bear −0.5x per 10pp, Bull +0.5x per 10pp

**Custom mode:** Reverts to full manual control where each scenario has its own complete assumption set. This is the escape hatch for analysts who need Bear to model a specific downside that doesn't map to a uniform spread.

## 2. Calculator Changes

### Add Linked Scenario Calculation

In `shared/calculators/value-creation.calc.ts`, add a new function:

```typescript
export interface LinkedScenarioConfig {
  rangePercent: number;  // e.g. 10, 20, 30
}

export function calculateLinkedScenarios(
  baseYear: BaseYearData,
  baseAssumptions: YearAssumptions[],
  synergies: SynergyInput[],
  fundingLines: FundingLineForProjection[],
  exitAssumptions: ExitAssumptions,
  config: LinkedScenarioConfig
): { 
  bear: ProjectedYear[]; 
  base: ProjectedYear[]; 
  bull: ProjectedYear[];
  derivedAssumptions: {
    bear: { revenueGrowthOffset: number; cosGrowthOffset: number; overheadGrowthOffset: number; exitMultipleOffset: number };
    bull: { revenueGrowthOffset: number; cosGrowthOffset: number; overheadGrowthOffset: number; exitMultipleOffset: number };
  };
  derivedExitAssumptions: {
    bear: ExitAssumptions;
    base: ExitAssumptions;
    bull: ExitAssumptions;
  };
} {
  const range = config.rangePercent;
  
  // Derive bear/bull offsets from range
  const bearRevenueOffset = -range;                     // Full range reduction on revenue
  const bearCosOffset = range * 0.5;                    // Half range increase on CoS (margin squeeze)
  const bearOverheadOffset = range * 0.2;               // Slight overhead pressure
  const bearExitMultipleOffset = -(range / 10) * 0.5;   // -0.5x per 10pp of range
  
  const bullRevenueOffset = range;                      // Full range increase on revenue
  const bullCosOffset = -(range * 0.5);                 // Half range decrease on CoS (margin expansion)
  const bullOverheadOffset = -(range * 0.2);            // Slight overhead improvement
  const bullExitMultipleOffset = (range / 10) * 0.5;    // +0.5x per 10pp of range
  
  // Build bear assumptions by adjusting base
  const bearAssumptions = baseAssumptions.map(a => ({
    ...a,
    revenueGrowthPercent: a.revenueGrowthPercent + bearRevenueOffset,
    costOfSalesGrowthPercent: a.costOfSalesGrowthPercent + bearCosOffset,
    staffCostGrowthPercent: a.staffCostGrowthPercent + bearOverheadOffset,
    adminCostGrowthPercent: a.adminCostGrowthPercent + bearOverheadOffset,
  }));
  
  // Build bull assumptions by adjusting base
  const bullAssumptions = baseAssumptions.map(a => ({
    ...a,
    revenueGrowthPercent: a.revenueGrowthPercent + bullRevenueOffset,
    costOfSalesGrowthPercent: a.costOfSalesGrowthPercent + bullCosOffset,
    staffCostGrowthPercent: a.staffCostGrowthPercent + bullOverheadOffset,
    adminCostGrowthPercent: a.adminCostGrowthPercent + bullOverheadOffset,
  }));
  
  // Derive exit assumptions per scenario
  const bearExit = { 
    ...exitAssumptions, 
    exitMultiple: Math.max(1, exitAssumptions.exitMultiple + bearExitMultipleOffset) 
  };
  const bullExit = { 
    ...exitAssumptions, 
    exitMultiple: exitAssumptions.exitMultiple + bullExitMultipleOffset 
  };
  
  return {
    bear: calculateProjections(baseYear, bearAssumptions, synergies, fundingLines),
    base: calculateProjections(baseYear, baseAssumptions, synergies, fundingLines),
    bull: calculateProjections(baseYear, bullAssumptions, synergies, fundingLines),
    derivedAssumptions: {
      bear: { revenueGrowthOffset: bearRevenueOffset, cosGrowthOffset: bearCosOffset, overheadGrowthOffset: bearOverheadOffset, exitMultipleOffset: bearExitMultipleOffset },
      bull: { revenueGrowthOffset: bullRevenueOffset, cosGrowthOffset: bullCosOffset, overheadGrowthOffset: bullOverheadOffset, exitMultipleOffset: bullExitMultipleOffset },
    },
    derivedExitAssumptions: {
      bear: bearExit,
      base: exitAssumptions,
      bull: bullExit,
    },
  };
}
```

**Important:** The existing `calculateScenarios()` function stays for backward compatibility (Custom mode still uses it). The new `calculateLinkedScenarios()` is called when `scenarioMode === 'linked'`.

### Update Return Calculations for Linked Mode

When in Linked mode, returns for each scenario need to use per-scenario exit assumptions (bear gets lower exit multiple, bull gets higher). In `ValueCreationModeller.tsx`, the `scenarioComparison` useMemo needs to branch based on scenario mode:

```typescript
const scenarioComparison = useMemo(() => {
  // ... existing null checks ...
  
  const baseScenario = vcData.scenarios.find(s => s.scenarioType === 'base');
  if (!baseScenario) return null;
  
  const isLinked = baseScenario.scenarioMode === 'linked';
  const range = toNum(baseScenario.rangePercent) || 10;
  
  if (isLinked) {
    const result = calculateLinkedScenarios(
      baseYearData, baseAssumptions, baseSynergies, fundingLineInputs,
      exitAssumptions, { rangePercent: range }
    );
    
    // Calculate returns using per-scenario exit assumptions
    const bearReturns = calculateReturns(result.bear, result.derivedExitAssumptions.bear, entryEquity, entryMultiple, totalDebt, totalFees, fundingLineInputs);
    const baseReturns = calculateReturns(result.base, result.derivedExitAssumptions.base, entryEquity, entryMultiple, totalDebt, totalFees, fundingLineInputs);
    const bullReturns = calculateReturns(result.bull, result.derivedExitAssumptions.bull, entryEquity, entryMultiple, totalDebt, totalFees, fundingLineInputs);
    
    return {
      projections: { bear: result.bear, base: result.base, bull: result.bull },
      returns: { bear: bearReturns, base: baseReturns, bull: bullReturns },
      derivedAssumptions: result.derivedAssumptions,
      derivedExitAssumptions: result.derivedExitAssumptions,
      isLinked: true,
      rangePercent: range,
    };
  } else {
    // Existing custom mode logic — keep entirely as-is
    // Uses revenueGrowthMultiplier / costPressureAdjustment from scenario rows
    // ...
  }
}, [/* deps */]);
```

## 3. API Changes

### Update Scenario Endpoints

The existing PUT endpoint for scenarios needs to accept the new fields:

```
PUT /api/v2/value-creation/scenarios/:id

```

Validation:
- `scenarioMode` must be either `'linked'` or `'custom'`
- `rangePercent` must be a positive number between 1 and 50
- Only the base scenario row stores `scenarioMode` and `rangePercent`

No new endpoints needed. Existing bulk assumption update, exit update, and synergy CRUD all work unchanged.

- The growth assumptions section ONLY shows base case inputs (same as current single-scenario view)

## 5. Changes to `ValueCreationModeller.tsx`

### Derive Scenario Mode from Data

```typescript
const scenarioMode = useMemo<'linked' | 'custom'>(() => {
  const baseScenario = vcData?.scenarios?.find(s => s.scenarioType === 'base');
  return (baseScenario?.scenarioMode as 'linked' | 'custom') || 'linked';
}, [vcData]);

const rangePercent = useMemo(() => {
  const baseScenario = vcData?.scenarios?.find(s => s.scenarioType === 'base');
  return toNum(baseScenario?.rangePercent) || 10;
}, [vcData]);
```

### Mutation for Mode/Range Changes

```typescript
const updateScenarioModeMutation = useMutation({
  mutationFn: async ({ scenarioId, data }: { scenarioId: number; data: Record<string, any> }) => {
    await apiRequest('PUT', `/api/v2/value-creation/scenarios/${scenarioId}`, data);
  },
  onSuccess: () => handleDataChange(),
});

const handleScenarioModeChange = (mode: 'linked' | 'custom') => {
  const baseScenario = vcData?.scenarios?.find(s => s.scenarioType === 'base');
  if (baseScenario) {
    updateScenarioModeMutation.mutate({ scenarioId: baseScenario.id, data: { scenarioMode: mode } });
  }
};

const handleRangeChange = (range: number) => {
  const baseScenario = vcData?.scenarios?.find(s => s.scenarioType === 'base');
  if (baseScenario) {
    updateScenarioModeMutation.mutate({ scenarioId: baseScenario.id, data: { rangePercent: String(range) } });
  }
};
```

## 7. What NOT to Change

- **Existing `calculateScenarios()` function** — keep for Custom mode backward compatibility
- **Bear/Bull scenario rows in the database** — keep them, Custom mode uses them
- **Synergy handling** — synergies are the same across all scenarios in both modes (they represent specific identified actions, not growth assumptions)
- **Sensitivity analysis** — continues to use base assumptions as its starting point regardless of mode
- **Exit Assumptions section in sidebar** — in Linked mode, the user sets the BASE exit multiple here, and bear/bull multiples are derived. In Custom mode, the exit multiple applies to whichever scenario is active.

## 9. Test Scenarios

1. **Linked mode default:** New deal models should default to Linked mode with ±10% range. Dashboard should show Bear/Base/Bull with derived values. Changing base revenue growth from 5% to 10% should automatically shift Bear to 0% and Bull to 20%.

2. **Range adjustment:** Change range from ±10% to ±20%. Bear revenue should widen (base − 20pp), Bull should widen (base + 20pp). CoS and overhead offsets should scale proportionally. Exit multiples should flex by ±1.0x (instead of ±0.5x at 10% range). Dashboard hero cards should update immediately.

3. **Live preview in sidebar:** The Linked mode preview grid in the assumptions panel should update in real-time as the user changes base assumptions OR the range. If base revenue is 5% and range is 10%, preview shows Bear −5%, Base 5%, Bull 15%.

4. **Switch to Custom mode:** Click Custom toggle. Bear/Base/Bull tabs should reappear in the top strip (on non-Dashboard tabs). Each scenario should retain its current derived values as starting points for manual editing. Switching back to Linked should re-derive Bear/Bull from the current base + range.

5. **Negative growth in Bear:** Base revenue growth 2%, range 10% → Bear = −8%. The calculator should handle negative revenue growth correctly throughout the P&L (revenue declines year over year, CoS still grows). Verify no division-by-zero or NaN in projections.

6. **Backward compatibility:** Existing deals created before this change should load with `scenarioMode = 'custom'` and work exactly as before. The old `revenueGrowthMultiplier` / `costPressureAdjustment` fields continue to drive Custom mode calculations.

7. **Persistence:** Change from Linked ±10% to Linked ±20%, reload the page. Should persist at ±20%. Switch to Custom, reload. Should stay Custom. Switch back to Linked, reload. Should be Linked.

8. **Synergies unchanged:** In both Linked and Custom mode, synergies should be identical across Bear/Base/Bull (they represent specific identified actions, not growth assumptions). Verify synergy values are the same in all three scenarios on the Dashboard.

9. **Sensitivity analysis:** Should continue to use base case assumptions as its starting point regardless of whether Linked or Custom mode is active. The tornado/heatmap/break-even calculations are independent of the scenario system.

10. **Per-scenario exit multiples:** In Linked mode, the three exit valuation cards should each show their own derived exit multiple (e.g. Bear 3.5x, Base 4.0x, Bull 4.5x at ±10% range). In Custom mode, all three use the same exit multiple as before.
