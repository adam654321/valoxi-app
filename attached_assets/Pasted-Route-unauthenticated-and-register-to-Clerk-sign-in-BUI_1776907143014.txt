Leave all other routes unchanged. Specifically:

- <Route path="/forgot-password"> stays (password reset still uses Express path)
- <Route path="/reset-password"> stays (same reason)
- <Route path="/auth/magic"> and <Route path="/auth/link-expired"> stay (magic link flows)

Rationale:
- / is the default URL. Users clicking the app logo or hitting the bare domain should land on Clerk sign-in, not a secondary Express form.
- /register may exist as a stale link in older docs, emails, or user bookmarks. Redirect to /sign-up instead of dead-ending at the legacy Register component.
- /login stays accessible for the magic link recovery flow which completes on /auth/magic and needs /login as a fallback target. This path only works for users who exist in the Express session path (rare post-Clerk).
- The clerkEnabled ternary means if Clerk is ever disabled server-side (VITE_CLERK_ENABLED=false or server /api/v2/public/config returns clerkEnabled: false), the legacy Login and Register components still render as before. Backward compatible.
