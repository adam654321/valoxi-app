PHASE 4C-2 FIX 2 — Explicit navigation inside signOut callback

PROBLEM FROM LAST TEST
Flag-on logout click: page did not navigate. Cookies cleared (proven by refresh showing logged-out state) but the browser stayed on the dashboard URL, so the SPA continued rendering the dashboard from React state. Root cause: in @clerk/react's current version, passing both a callback and a redirectUrl option causes redirectUrl to be ignored — the callback is treated as the caller taking responsibility for navigation.

FIX
Remove the redirectUrl option. Handle navigation explicitly inside the callback, immediately after Express logout resolves. This ensures both cookies are cleared before navigation, and does not depend on SDK behaviour when mixing callback and options.

STEP 1 — Modify client/src/components/layout/NavUser.tsx

Find the logoutMutation block. Find this section inside mutationFn:

      if (clerkEnabled) {
        // Callback form: runs after Clerk clears __session, before Clerk navigates.
        // Express logout inside the callback ensures sid is destroyed before redirect.
        // Explicit redirectUrl overrides the Clerk Dashboard "after sign-out" config.
        await signOut(
          async () => {
            await apiRequest("POST", "/api/v2/auth/logout");
          },
          { redirectUrl: "/sign-in" }
        );
        // Clerk handles the browser navigation after the callback resolves.
        // Code below this line will not execute in the flag-on path.
      } else {
        await apiRequest("POST", "/api/v2/auth/logout");
      }

Replace with:

      if (clerkEnabled) {
        // Callback form with explicit in-callback navigation.
        // Order inside callback: Express logout (clears sid), then navigate.
        // signOut() has already cleared __session before the callback runs.
        // We do NOT pass redirectUrl — @clerk/react ignores it when a callback
        // is present, which caused the previous iteration to hang on no-navigation.
        await signOut(async () => {
          await apiRequest("POST", "/api/v2/auth/logout");
          window.location.href = "/sign-in";
        });
        // Execution does not continue past signOut in practice because the
        // callback navigates, but leaving as-is for type correctness.
      } else {
        await apiRequest("POST", "/api/v2/auth/logout");
      }

The onSuccess handler stays exactly as it was after the previous edit — leave it untouched.
