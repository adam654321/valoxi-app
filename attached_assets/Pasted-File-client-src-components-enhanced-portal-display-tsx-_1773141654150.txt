File: client/src/components/enhanced-portal-display.tsx
Problem: The document type dropdown in the Stage 1 upload section shows all types regardless of what has already been analysed. The analysisCompletion data is never fetched at the EnhancedPortalDisplay component level, so no filtering can occur. Additionally, after a successful upload the analysis-completion cache is not invalidated, so even a fixed filter wouldn't refresh.
Change 1 — Add the analysisCompletion query to EnhancedPortalDisplay.
Locate the block of useQuery calls near the top of EnhancedPortalDisplay. After the existing documents query, add:
tsconst { data: analysisCompletion } = useQuery<{
  completedTypes: string[];
  missingTypes: string[];
  isComplete: boolean;
  completionPercentage: number;
  completedCount: number;
  totalCount: number;
}>({
  queryKey: [`/api/v2/portal-submit/${token}/analysis-completion`],
  enabled: !!token,
  refetchInterval: 10000,
  refetchIntervalInBackground: false,
  staleTime: 30000,
  select: (response: any) => response.data,
});
Change 2 — Apply filter logic to the dropdown.
Find the SelectContent block inside the Stage 1 upload card that currently reads:
tsx<SelectContent>
  {DOCUMENT_TYPES.map(type => (
    <SelectItem key={type.value} value={type.value} data-testid={`option-${type.value}`}>
      {type.label}
    </SelectItem>
  ))}
</SelectContent>
Replace it with:
tsx<SelectContent>
  {DOCUMENT_TYPES
    .filter(type => {
      if (!analysisCompletion) return true;
      switch (type.value) {
        case 'company_accounts': {
          const count = analysisCompletion.completedTypes.filter(t =>
            t.startsWith('company_accounts')
          ).length;
          return count < 5;
        }
        case 'asset_register':
          return !analysisCompletion.completedTypes.includes('asset_register');
        case 'balance_sheet':
          return !analysisCompletion.completedTypes.includes('balance_sheet');
        case 'p_and_l':
          return !analysisCompletion.completedTypes.includes('profit_and_loss');
        case 'sales_ledger':
          return !analysisCompletion.completedTypes.includes('sales_ledger');
        case 'staff_matrix':
          return !analysisCompletion.completedTypes.includes('staff_matrix');
        default:
          return true;
      }
    })
    .map(type => (
      <SelectItem key={type.value} value={type.value} data-testid={`option-${type.value}`}>
        {type.label}
      </SelectItem>
    ))
  }
</SelectContent>

Find submitDocumentMutation's onSuccess handler. It currently invalidates two queries. Add a third:
tsqueryClient.invalidateQueries({ queryKey: [`/api/v2/portal-submit/${token}/analysis-completion`] });
