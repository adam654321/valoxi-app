Step 3 Prompt for Replit

This is the final step of the schema split. All 6 domain files, the relations file, and the barrel index are created and verified with 217 matching exports. Now I need to swap the entire codebase over to use the new modular structure.
The approach is simple and safe: replace the contents of shared/schema.ts with a single re-export line, so every existing import path (@shared/schema or ../shared/schema etc.) continues to work without changing a single import statement anywhere in the codebase.

1. Back up the original schema file
Before making any changes, copy the original file:
cp shared/schema.ts shared/schema.ts.backup
2. Replace the contents of shared/schema.ts
Replace the entire file contents with:
typescript/**
 * Schema barrel file - re-exports all domain modules.
 * 
 * The schema is split into domain modules under shared/schema/:
 *   core.ts       - Users, companies, sessions, roles, invitations
 *   deals.ts      - Target companies, contacts, pipeline, activities, notes
 *   documents.ts  - Document storage, analysis, AI pipeline
 *   portal.ts     - External portal, submissions, chase-ups
 *   financials.ts - P&L, balance sheets, staff, assets, valuations
 *   dashboard.ts  - Dashboard widgets, alerts, composite types
 *   relations.ts  - All Drizzle relation definitions
 */
export * from './schema/index';
That's it. Every file in the codebase that imports from @shared/schema or any path resolving to shared/schema.ts will now get its exports via the barrel file, which re-exports from the domain modules.
3. Verify there are no direct imports to the old file that bypass the barrel
Search the entire project for any imports that reference shared/schema.ts explicitly (with the .ts extension) or that might resolve differently:

Search for from '@shared/schema' — these should all work (they resolve to shared/schema.ts which now re-exports)
Search for from '../../shared/schema' or similar relative paths — same, should work
Search for from '@shared/schema/ — if anyone imports directly from a subdirectory like @shared/schema/core, that's fine too, but check if any exist
Search for schema.ts in tsconfig.json paths or vite.config.ts aliases — confirm the @shared alias points to the shared directory

4. Verify drizzle.config.ts
Drizzle Kit uses the schema path for migrations. Check drizzle.config.ts — it likely has something like:
typescriptschema: './shared/schema.ts'
```

This should still work because `shared/schema.ts` re-exports everything. But if Drizzle Kit needs to discover all tables, it must be able to follow the re-exports. Test by running:
```
npx drizzle-kit generate
or whichever drizzle-kit command you normally use. If it fails to find tables, you may need to change the schema config to:
typescriptschema: './shared/schema/*.ts'
or
typescriptschema: ['./shared/schema/core.ts', './shared/schema/deals.ts', './shared/schema/documents.ts', './shared/schema/portal.ts', './shared/schema/financials.ts', './shared/schema/dashboard.ts', './shared/schema/relations.ts']
```

But try the simple re-export approach first — it usually works.
```
