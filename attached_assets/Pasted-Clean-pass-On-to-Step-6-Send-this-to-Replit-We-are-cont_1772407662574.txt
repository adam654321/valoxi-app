Create server/routes/billing.routes.ts with a single endpoint:
POST /webhook/stripe
This route must NOT have requireActiveSubscription or any auth middleware — it is called by Stripe directly, not by a logged-in user.
The handler must:

Verify the Stripe webhook signature using stripe.webhooks.constructEvent(rawBody, signature, webhookSecret). If verification fails, return 400 with { error: 'invalid_signature' }.
Check billingRepository.getEventByStripeId(event.id) — if already processed, return 200 with { received: true, skipped: true } (idempotency at the route level as a safety net on top of the service-level check).
Handle the following Stripe event types, calling the appropriate billingService method for each. For any event type not in this list, return 200 with { received: true, unhandled: true } — never return an error for unknown event types as this would cause Stripe to retry.

Event handlers:
checkout.session.completed — extract customer, subscription, metadata.userCompanyId, metadata.planKey, metadata.billingInterval from the session object. Call billingService.activateSubscription. Log the raw event payload to webhookEvents table (existing table in shared/schema/core.ts) with source: 'stripe'.
customer.subscription.updated — extract customer, id (subscription ID), status, current_period_start, current_period_end, cancel_at_period_end, and items.data[0].price.lookup_key (to derive planKey). Call billingService.updateSubscriptionStatus. Log to webhookEvents.
customer.subscription.deleted — extract subscription ID and customer. Call billingService.updateSubscriptionStatus with status: 'canceled'. Log to webhookEvents.
invoice.paid — update currentPeriodStart and currentPeriodEnd from the invoice, set status active. Call billingService.updateSubscriptionStatus. Log to webhookEvents.
invoice.payment_failed — set status past_due. Call billingService.updateSubscriptionStatus. Log to webhookEvents.

Always return 200 for successfully processed events. Never return 4xx/5xx after signature verification passes unless there is a genuine processing error — Stripe will retry on non-200 responses.
All errors inside event processing must be caught and logged (console.error) but must still return 200 to prevent Stripe retries. Log the error to the webhookEvents table with status: 'error' and the error message in the error field.
