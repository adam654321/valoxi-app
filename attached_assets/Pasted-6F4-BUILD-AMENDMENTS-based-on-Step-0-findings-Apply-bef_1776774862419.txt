Amendment C: exact body of createFiveDNewMemberTrial

Replace the Step 2 body with this. Place it directly after createTrialSubscription in server/services/billing.service.ts, as a sibling method on the same class with identical visibility.

  async createFiveDNewMemberTrial(userCompanyId: number): Promise<Subscription> {
    const now = new Date();
    const trialEnd = new Date(now);
    trialEnd.setMonth(trialEnd.getMonth() + 6);

    const subscription = await billingRepository.create({
      userCompanyId,
      planKey: 'CORE',
      status: 'trialing',
      trialStart: now,
      trialEnd,
      trialEndsAt: trialEnd,
      freeMonthsStartedAt: now,
      freeMonthsTotal: 6,
    });

    await billingRepository.logEvent({
      userCompanyId,
      eventType: 'trial.started',
      newStatus: 'trialing',
      newPlanKey: 'CORE',
      payload: { trialDays: null, freeMonthsTotal: 6, variant: '5d_new_member' },
    });

    const { track } = await import('./funnel.service');
    track(userCompanyId, null, 'trial.started', { planKey: 'CORE', freeMonthsTotal: 6, variant: '5d_new_member' });

    console.log(`[billing] created 5D New Member trial userCompanyId=${userCompanyId} trialEndsAt=${trialEnd.toISOString()}`);

    return subscription;
  }

Notes:
- Uses setMonth(+6) rather than addMonths from date-fns because createTrialSubscription uses raw Date arithmetic, not a library. Matching the existing style.
- trialStart, trialEnd, trialEndsAt mirror createTrialSubscription's column-writing pattern. The cron at Step 0c checks both trialEnd AND trialEndsAt, so writing both keeps the expiry cron firing correctly in 6F8.
- Event type stays trial.started to keep reporting uniform. The payload.variant distinguishes 5D New Member in downstream analytics without needing a new event type.
- No stripeCustomerId or stripeSubscriptionId fields are passed; billingRepository.create will default them to null per the schema.
