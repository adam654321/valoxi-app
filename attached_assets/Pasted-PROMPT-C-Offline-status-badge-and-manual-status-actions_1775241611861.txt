PROMPT C — Offline status badge and manual status actions in DocumentRow
We are completing the offline document flow UI. The Send Without Portal panel is now in place. When a buyer downloads a document offline it gets delivery_method of offline in the database. The DocumentRow component inside DealDocumentsSummary.tsx needs to recognise offline documents and show manual status actions instead of the Send to Seller button. In client/src/components/deal-documents/DealDocumentsSummary.tsx make the following changes to the DocumentRow component only.
First find where the document type badge or status badge is rendered for each document row. When the latest document has deliveryMethod equal to the string offline add a small secondary badge alongside the status badge showing the text Offline in muted styling — use variant outline with text-xs and a muted foreground colour.
Second find the Send to Seller button — it currently shows when status === ‘draft’ and generatedFileUrl is set. Add a condition: if the document has deliveryMethod of offline do not show the Send to Seller button at all regardless of status.
Third when deliveryMethod equals offline and status is draft or downloaded show a single button saying Mark as Sent in variant outline size sm. When clicked it should open a small inline confirmation section — not a Dialog, just a conditional div that expands below the button within the row. The expanded section should show a date input defaulting to today’s date, a textarea placeholder saying Optional notes e.g. sent by email on 3 April, and two buttons: Confirm Sent which calls POST /api/v2/deal-documents/the document id/manual-status with body status sent and the date and notes values, and Cancel which collapses the section. Use useMutation from tanstack react-query for this call and invalidate the deal documents query on success using the same queryKey pattern already used elsewhere in the file.
Fourth when deliveryMethod equals offline and status is sent show three buttons in a row: Accepted, Rejected, and Countered each in variant outline size sm with appropriate colours — green for Accepted, red for Rejected, amber for Countered. Each button when clicked should open the same inline confirmation section with a date input and notes textarea and a Confirm button that calls POST /api/v2/deal-documents/the document id/manual-status with the corresponding status value. Invalidate the query on success.
Use local component state within DocumentRow for the inline confirmation visibility and form values — add useState hooks for showConfirm as boolean, confirmDate as string defaulting to today in YYYY-MM-DD format, and confirmNotes as string. Do not open any Dialog or Modal — keep everything inline within the existing row layout.
