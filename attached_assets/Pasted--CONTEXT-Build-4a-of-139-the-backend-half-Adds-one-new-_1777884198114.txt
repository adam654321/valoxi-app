endpoint that returns whether a given target company has an active chase-up
schedule and the portalTokenId of that schedule. The frontend (Build 4b)
needs this to decide whether to show the chase-up section in the analysis
trigger dialog and to know which token to call manual-stop against.

[DESIGN]

New endpoint:
GET /api/v2/chase-up/active-for-target/:targetCompanyId

Auth: same middleware stack as the rest of the chase-up router
(isAuthenticated, validateCsrfToken on non-GETs, requireActiveSubscription,
requirePermission('canCreateDeals')). GET so no CSRF needed on this one.

Query: parse targetCompanyId from URL as integer, validate it. Read
req.session.userCompanyId and assert non-null. Run a single SELECT joining
chase_up_schedules to portal_access_tokens with the following filter:

  portal_access_tokens.userCompanyId = req.session.userCompanyId!
  AND chase_up_schedules.targetCompanyId = :targetCompanyId
  AND chase_up_schedules.isActive = true
  AND chase_up_schedules.isCompleted = false

Project chase_up_schedules.portalTokenId. Use limit(1) since there should
be at most one active+incomplete schedule per (userCompany, targetCompany)
pair.

Tenant scope is via portal_access_tokens.userCompanyId, matching the
existing pattern in getChaseUpDashboard. Do NOT scope via target_companies.

Response shape:
  { hasActiveSchedule: boolean, portalTokenId: number | null }

Use the standard sendSuccess wrapper so the full response body is:
  { success: true, data: { hasActiveSchedule, portalTokenId } }
