Context: We are fixing a critical multi-tenancy security vulnerability in this M&A CRM application. Every tenant (acquiring organisation) is identified by a userCompanyId stored in the user's session. No tenant must ever be able to access another tenant's data.
The problem: server/routes/financial-data.routes.ts contains 10 GET endpoints, none of which check req.session.userCompanyId before returning data. Any authenticated user can retrieve full financial data (P&L, balance sheets, staff, loans, etc.) for any company in the database by guessing integer IDs in the URL.
The fix required: Apply the established tenant isolation pattern — the same one used in server/routes/target-companies.routes.ts — to every endpoint in financial-data.routes.ts. The approach is:

Extract userCompanyId from the session at the top of each handler
Throw UnauthorizedError if it is missing
Verify that the requested targetCompanyId belongs to that tenant before returning any data, using targetCompaniesRepository.getById(targetCompanyId, userCompanyId) — this already exists and returns undefined if the company doesn't belong to the tenant
Throw NotFoundError if ownership cannot be confirmed

typescriptrouter.get('/company/:companyId/periods', asyncHandler(async (req: Request, res: Response) => {
  const userCompanyId = req.session?.userCompanyId;
  const targetCompanyId = parseInt(req.params.companyId);
