# Step 3 of 8 — Restructure the Screening Report

## Context

Steps 1 and 2 are complete:
- SynthesisReportView built and wired in (Step 1)
- NarrativeBlock moved to top of all 7 expert reports (Step 2)

This step restructures the Screening report view only.
Do not touch any other component.

The Screening report is the first thing users see after Phase 1 completes.
It currently renders the recommendation badge and score at the top, which is good,
but the dimension scorecard (the 6 RAG-rated sub-dimensions) is buried and the
questions for seller are not visually distinct.

---

## The Build

### Step 3a — Read the current ScreeningReportView
Read `client/src/components/analysis/ExpertReportViews.tsx`.
Find ScreeningReportView and map out exactly what it currently renders and in what order.
Identify the field names used for:
- recommendation (the PROCEED/CAUTION/NO-GO value)
- overall_score
- recommendation_justification
- executive_summary
- comparable_context
- dimensions (the 6 sub-dimension objects)
- key_strengths[]
- key_concerns[]
- questions_for_seller[]

### Step 3b — Reorder ScreeningReportView to this structure:

**Section 1 — Recommendation banner (keep existing, just confirm it is at top)**
Large recommendation badge — PROCEED / PROCEED_WITH_CAUTION / NO_GO
Colour coded: green / amber / red
Score: overall_score / 100
This should already be first — confirm and leave as-is.

**Section 2 — Recommendation justification**
Render data.recommendation_justification as a plain prose paragraph.
Label: none needed — it reads naturally after the verdict.
If executive_summary also exists as a separate field, render it here too
(check whether both fields exist or just one).

**Section 3 — Comparable context**
Render data.comparable_context as an italicised paragraph.
Wrap in a subtle container — this is the sector benchmark context.
Label: "Sector Context" or similar.
Only render if the field is present and non-empty.

**Section 4 — Dimension Scorecard**
This is the most important restructuring change in this step.
The 6 dimensions should render as a 2-column grid of compact tiles.
The dimensions are inside data.dimensions and are:
  earnings_trajectory, balance_sheet_health, cash_reality,
  customer_risk, asset_quality, people_capability

For each dimension tile render:
  - Dimension name (formatted: replace underscores with spaces, title case)
  - RAG dot / badge (data.dimensions[key].rag — GREEN / AMBER / RED)
  - Score: data.dimensions[key].score / 100
  - One-line explanation: data.dimensions[key].explanation
    (truncate to ~120 chars with ellipsis if longer — this is a summary tile, not a full view)

RAG colour mapping:
  GREEN = green background/border
  AMBER = amber background/border
  RED = red background/border

Use a 2-column CSS grid. On mobile it can stack to 1 column.
Label the section: "Dimension Breakdown"

**Section 5 — Key Strengths**
Bulleted list from data.key_strengths[]
Use green bullet points or a green left border to distinguish from concerns.
Label: "Key Strengths"
Only render if array is non-empty.

**Section 6 — Key Concerns**
Bulleted list from data.key_concerns[]
Use amber/red bullet points or amber left border.
Label: "Key Concerns"
Only render if array is non-empty.

**Section 7 — Questions for Seller**
Numbered list from data.questions_for_seller[]
Render inside a visually distinct highlighted box:
  - Slightly different background colour (e.g. light blue or light amber)
  - A clear label: "Questions to Ask the Seller"
  - Each question numbered
This makes them easy to copy and use in a seller conversation.
Only render if array is non-empty.

### Step 3c — Null safety
All sections should be guarded — if a field is missing or the array is empty, skip that section.
Do not render empty section headers.

### Step 3d — What NOT to change in this step
- Do not touch SynthesisReportView (Step 1)
- Do not move narratives in other views (Step 2, already done)
- Do not change FinancialReportView, OperationalReportView, RiskReportView,
  QoEReportView, SectorReportView, ValuationReportView, DealStructureReportView
- Do not touch ExpertAnalysisDashboard.tsx
- Do not touch any API routes or data fetching
