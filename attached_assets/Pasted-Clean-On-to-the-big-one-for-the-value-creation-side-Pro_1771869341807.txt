Bug 1: NumericStepper blocks empty input and free typing
Current implementation:
jsfunction NumericStepper({ value, onChange, ... }) {
  const clamp = (v: number) => Math.min(max, Math.max(min, Math.round(v * 100) / 100));
  
  return (
    <Input
      type="number"
      value={value}  // ← bound to number prop directly
      onChange={e => {
        const v = parseFloat(e.target.value);
        if (!isNaN(v)) onChange(clamp(v));  // ← rejects empty string, clamps every keystroke
      }}
    />
  );
}
Problems:

parseFloat("") is NaN, so the !isNaN(v) check rejects it. You cannot clear a field to type a new value.
value={value} binds to a number, so React immediately snaps the display back to the old number when the onChange doesn't fire.
clamp() runs on every keystroke, so typing "-5" is impossible because typing "-" alone gives NaN.
The user is forced to select-all and type over, or use the +/- buttons. This feels broken.

Fix for NumericStepper: Add internal string state for the display value. The value prop (number) syncs the display on external changes. Free typing is allowed via string state. Parsing, clamping, and calling onChange only happens on blur.
jsfunction NumericStepper({ value, onChange, step = 0.5, min = -50, max = 100, unit = '%', disabled = false }) {
  const clamp = (v: number) => Math.min(max, Math.max(min, Math.round(v * 100) / 100));
  const [display, setDisplay] = useState(String(value));
  const prevValueRef = useRef(value);

  // Sync display from parent when value changes externally (not from our own edits)
  useEffect(() => {
    if (value !== prevValueRef.current) {
      setDisplay(String(value));
      prevValueRef.current = value;
    }
  }, [value]);

  const commitValue = () => {
    const v = parseFloat(display);
    if (!isNaN(v)) {
      const clamped = clamp(v);
      onChange(clamped);
      setDisplay(String(clamped));
      prevValueRef.current = clamped;
    } else {
      // Reset to last known good value
      setDisplay(String(value));
    }
  };

  return (
    <div className="flex items-center gap-0.5">
      <Button
        variant="outline"
        size="icon"
        className="h-7 w-7 shrink-0"
        onClick={() => {
          const clamped = clamp(value - step);
          onChange(clamped);
          setDisplay(String(clamped));
          prevValueRef.current = clamped;
        }}
        disabled={disabled || value <= min}
      >
        <span className="text-sm">&minus;</span>
      </Button>
      <div className="relative w-16">
        <Input
          type="text"
          inputMode="decimal"
          value={display}
          onChange={e => setDisplay(e.target.value)}
          onBlur={commitValue}
          onKeyDown={e => { if (e.key === 'Enter') commitValue(); }}
          disabled={disabled}
          className="h-7 text-xs text-center pr-5"
        />
        <span className="absolute right-1.5 top-1/2 -translate-y-1/2 text-[10px] text-muted-foreground pointer-events-none">
          {unit}
        </span>
      </div>
      <Button
        variant="outline"
        size="icon"
        className="h-7 w-7 shrink-0"
        onClick={() => {
          const clamped = clamp(value + step);
          onChange(clamped);
          setDisplay(String(clamped));
          prevValueRef.current = clamped;
        }}
        disabled={disabled || value >= max}
      >
        <span className="text-sm">+</span>
      </Button>
    </div>
  );
}
Key changes:

type="text" with inputMode="decimal" instead of type="number" (avoids browser number input quirks)
Internal display string state allows free typing
commitValue on blur and Enter key — parses, clamps, calls onChange, updates display
+/- buttons update display immediately alongside calling onChange
prevValueRef prevents the sync useEffect from overwriting during own edits
Removed the old [appearance:textfield] and spinner-hiding CSS (no longer needed with type="text")
