Step 1 of 8 — Build SynthesisReportView Component
Context for the agent
We are redesigning the expert analysis report display. This is the first of 8 steps.
Each step is self-contained. Do not work ahead.
The expert analysis system has two main files:

client/src/components/analysis/ExpertAnalysisDashboard.tsx — card layout (DO NOT TOUCH)
client/src/components/analysis/ExpertReportViews.tsx — all report view components (THIS FILE)

Currently the Synthesis expert report has no dedicated view component. It falls through
to GenericReportView which renders a wall of unstyled text. This is the most important
report in the system and currently the worst presented.
This step builds a complete SynthesisReportView component and wires it in.
Do not change anything else in this step.

The Build
Step 1a — Read the file first
Read client/src/components/analysis/ExpertReportViews.tsx in full.
Identify:

Where GenericReportView is defined
Where the getReportViewForExpert() switch statement is
What shared primitives already exist (ScoreRing, RagBadge, NarrativeBlock, SectionCard, etc.)
The existing pattern used by other report views so SynthesisReportView follows the same conventions

Step 1b — Build SynthesisReportView
Add a new SynthesisReportView component to ExpertReportViews.tsx.
Use the same styled primitives that already exist in the file.
The component receives data which is the analysisData JSON from the synthesis expert result.
Render these sections in this order:
Section 1 — Verdict Hero
Full-width banner. Large recommendation text (replace underscores with spaces).
Colour coding: STRONG_PROCEED / PROCEED = green, PROCEED_WITH_CAUTION = amber,
DO_NOT_PROCEED / NO_GO / DO_NOT_PROCEED = red.
Overall score shown prominently: "{score} / 100"
Subtext: "Combined verdict across 8 specialist expert analyses"
Section 2 — Executive Summary
Render data.executive_summary as readable prose.
Label: "Executive Summary"
Section 3 — Scores Dashboard
All 7 experts in a horizontal/grid layout.
For each key in data.scores_dashboard (financial, operational, risk, quality_of_earnings,
sector, valuation, deal_structure):

Display name (capitalise, replace underscores with spaces)
Score /100
Colour-coded score bar (green ≥70, amber ≥40, red <40)
Confidence badge

Section 4 — Valuation Snapshot
Three columns: Conservative | Base | Mid (from data.valuation_summary.equity_value_range)
Format as £XXX,XXX
Below: Recommended offer + Recommended structure as a badge
Section 5 — Expert Consensus
Subsection: "Where experts agreed" — bullet list from data.expert_consensus.agreements
Subsection: "Where experts disagreed" — for each item in data.expert_consensus.contradictions:
Render a two-column comparison card:
Left: expert_a name + expert_a_view
Right: expert_b name + expert_b_view
Below both: "Resolution:" + resolution text
Section 6 — Devil's Advocate
Amber/warning styled container.
Worst case scenario as a paragraph.
Weakest assumptions as a bullet list.
Underweighted risks as a bullet list.
Section 7 — Investment Thesis
Positive case as a paragraph.
Conditions for success as a numbered list.
Integration priorities (100 days) as a numbered list.
Section 8 — Information Requests
Three groups: Critical (red) | Important (amber) | Nice to Have (grey)
For each item: request text (bold) + source_expert badge + rationale text below.
Only render a group if it has items. Skip empty groups.
Section 9 — Investment Memorandum
Render data.narrative_report.
This is long-form text with section headers in ALL CAPS (e.g. "EXECUTIVE OVERVIEW").
Parse the text: any line that is entirely uppercase and non-empty → render as an h3/heading.
All other lines → render as prose paragraphs.
Wrap in a subtle bordered container labelled "Investment Memorandum".
Step 1c — Wire it in
In the getReportViewForExpert() switch statement, add:
case 'synthesis':
return <SynthesisReportView data={data} />;
Place it BEFORE the default/generic fallthrough.
Step 1d — Null safety
All fields should be treated as optional. If a field is missing or null, skip that section
gracefully — do not throw or render an empty box.

What NOT to change in this step

Do not touch ExpertAnalysisDashboard.tsx
Do not move narratives in other report views (that is Step 2)
Do not change GenericReportView
Do not change any other expert view components
Do not touch any API routes or data fetching
