We are starting Stage 3. Step 1: the guided activation flow — the sequence that takes a new user from a blank account to their first completed deal pack. The activation event is: Create target → Upload docs → Generate analysis → Save model → Generate HoT/offer. This is the moment the value of the platform becomes obvious and predicts conversion and retention.
Context from audit:

New users land on the dashboard with all-zero widgets and no guidance
The only signposting is three quick-action cards buried at the bottom
No welcome email is sent on registration
No default pipeline stages are created
No demo or sample data exists
Registration creates only a UserCompany and User row, then sets the session

Task 1 — Onboarding state tracking:
Add three columns to the users table in shared/schema/core.ts:

onboardingCompleted boolean, default false, NOT NULL
onboardingStep varchar(50), default 'create_target', nullable — tracks which step they are on
onboardingCompletedAt timestamp, nullable

Run db:push after. Do not create a separate onboarding table — these three columns on the users table are sufficient.
Task 2 — Default pipeline stages on registration:
In server/routes/auth.routes.ts, after creating the UserCompany and User records on registration, seed default pipeline stages for the new company. Look at the pipelineStages table schema and the existing pipeline seeding logic to understand the correct structure. Create the following default stages in order:

New Target
Initial Contact
Documents Requested
Under Review
Offer Stage
Heads of Terms
Due Diligence
Legal & Accounting
Completion
Not Qualified

These stages should be company-scoped (linked to the new userCompanyId). If stages already exist for a company, do not duplicate them.
Task 3 — Welcome email on registration:
In server/routes/auth.routes.ts, after successful registration, send a welcome email using the existing Nodemailer/email service. Look at how other emails are sent in the codebase (invitation emails, portal emails) and follow the same pattern.
Email content:

Subject: "Welcome to Rubicon — let's run your first deal"
Body (plain text + simple HTML): Welcome the user by first name. Tell them their account is set up and their free trial has started. Give them three numbered steps: 1) Add your first target company, 2) Upload their financial documents, 3) Generate your first expert analysis. Include a single CTA button linking to the app URL. Sign off from "The Rubicon Team". Keep it short — under 200 words.

Do not block the registration response waiting for the email — fire and forget (catch and log any email errors, do not surface them to the user).
Task 4 — Activation checklist component:
Create client/src/components/onboarding/ActivationChecklist.tsx:
A card component that shows at the top of the dashboard for users where onboardingCompleted === false. It should be dismissible (clicking X marks it dismissed for the session via local component state — not permanently, so it reappears on next login until fully completed).
The checklist has 5 steps — each with a title, short description, a CTA button, and a completion indicator (grey circle → green tick when done):

Add your first target company — "Find a business you want to evaluate and add it to your pipeline." CTA: "Add Target" → opens the existing AddTargetCompanyButton dialog or links to /target-companies
Upload financial documents — "Upload accounts or financial statements for AI analysis." CTA: "Go to Target" → links to the target company detail page (disabled/greyed if no target companies exist yet)
Generate expert analysis — "Run the AI analysis to get a full commercial due diligence report." CTA: "Run Analysis" → links to target company detail (disabled if no documents uploaded)
Save your deal model — "Set your offer price, funding stack, and DSCR." CTA: "Open Deal Modeller" → links to deal modeller tab
Generate an offer or HoT — "Create your offer letter or heads of terms and send it to the seller." CTA: "Generate Document" → links to deal documents tab

Completion detection: The component fetches completion state from a new API endpoint (see Task 5). Each step shows as complete based on the API response. When all 5 steps are complete, show a congratulations message: "You've completed your first deal pack — you're ready to buy a business." with a green banner, then call the API to mark onboarding as complete so the checklist stops appearing.
Style: use shadcn Card, use a progress bar (shadcn Progress component) showing X of 5 steps complete at the top of the card. Clean, encouraging, not childish. Consistent with the existing app design tokens.
Task 5 — Activation progress API endpoint:
Add GET /api/v2/onboarding/progress to a new route file server/routes/onboarding.routes.ts. This endpoint:

Requires isAuthenticated only (no CSRF — GET request)
Returns:

typescript{
  steps: {
    createTarget: boolean,    // true if user's company has at least 1 target company
    uploadDocuments: boolean, // true if any target company has at least 1 document
    generateAnalysis: boolean, // true if any expert analysis result exists for the company
    saveModel: boolean,       // true if any deal model has been saved
    generateDocument: boolean // true if any deal document (offer/HoT) has been generated
  },
  completedCount: number, // 0-5
  onboardingCompleted: boolean // from users.onboardingCompleted
}
Add POST /api/v2/onboarding/complete — marks onboardingCompleted = true and onboardingCompletedAt = now on the current user. Called by the frontend when all 5 steps are done.
Register both routes in server/routes/index.ts under /api/v2/onboarding with isAuthenticated middleware only.
