Context: We are continuing a systematic security audit of this multi-tenant M&A CRM. We are now fixing the final repository-level tenant isolation gap — document update and delete operations that have no tenant scoping in their SQL WHERE clauses.
The problem: In server/repositories/documents.repository.ts, the updateDocument and deleteDocument methods filter only by documentId with no tenant check at the database level:
typescriptasync updateDocument(documentId: number, document: Partial<InsertDocument>): Promise<Document | undefined> {
  const [updatedDocument] = await db
    .update(documents)
    .set(document)
    .where(eq(documents.id, documentId)); // ❌ No tenant check
  return updatedDocument || undefined;
}

async deleteDocument(documentId: number): Promise<boolean> {
  // ...
  const [deletedDocument] = await db
    .delete(documents)
    .where(eq(documents.id, documentId)); // ❌ No tenant check
  return !!deletedDocument;
}
The service layer currently calls getDocument(documentId, userCompanyId) before these operations as a separate check, but this is fragile — the protection exists only because of calling convention, not because the database query itself enforces it. Any future refactor or direct repository call bypasses it silently.
The documents table does not have a direct userCompanyId column — ownership is established via a join: documents.targetCompanyId → targetCompanies.userCompanyId. The getDocument method already demonstrates the correct pattern using this join.
The fix: Add a userCompanyId parameter to both updateDocument and deleteDocument, and enforce ownership in the WHERE clause via a subquery, matching the pattern already used in getDocument.
Specific instructions:
In server/repositories/documents.repository.ts:
Update updateDocument to verify ownership via subquery:
typescriptasync updateDocument(documentId: number, document: Partial<InsertDocument>, userCompanyId: number): Promise<Document | undefined> {
  const [updatedDocument] = await db
    .update(documents)
    .set(document)
    .where(and(
      eq(documents.id, documentId),
      inArray(
        documents.targetCompanyId,
        db.select({ id: targetCompanies.id })
          .from(targetCompanies)
          .where(eq(targetCompanies.userCompanyId, userCompanyId))
      )
    ))
    .returning();
  return updatedDocument || undefined;
}

The cascade deletes of related records (analysis results, access logs, upload events) that happen before it do not need the tenant check since they are scoped by documentId which has already been validated:

    .delete(documents)

      )
    ))
    .returning();
  return !!deletedDocument;
}
