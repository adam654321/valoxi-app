Replit Development Prompt 1: System Foundation & Database Setup
System Overview
You are building an M&A (Mergers & Acquisitions) CRM platform that helps business buyers track and manage potential acquisition targets through their deal pipeline.
User Structure (CRITICAL - Read Carefully)
Users: M&A professionals, business buyers, investment firms who are LOOKING TO ACQUIRE businesses
Target Companies: Businesses that users want to potentially ACQUIRE (these are NOT the users' companies)
User Companies: The organizations that employ the users (the acquiring companies/investment firms)

Example: John works for "ABC Investment Partners" (user company). He uses this CRM to track "XYZ Manufacturing" and "Local Restaurant Chain" (target companies) that ABC Investment Partners might want to acquire.
Core System Purpose
This CRM tracks potential acquisition targets through a pipeline from initial identification to deal completion. Users input information about businesses they want to buy, not businesses they own.
What You Need to Build in This Prompt
1. Project Setup
Create a new Node.js project with Express
Set up basic folder structure
Install essential dependencies
Configure environment variables
2. Database Schema
Create these essential tables with proper relationships:

-- User companies (the acquiring organizations)
CREATE TABLE user_companies (
  id SERIAL PRIMARY KEY,
  company_name VARCHAR(255) NOT NULL,
  email VARCHAR(255),
  phone VARCHAR(50),
  address TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Users (M&A professionals who use the system)
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  first_name VARCHAR(100) NOT NULL,
  last_name VARCHAR(100) NOT NULL,
  user_company_id INTEGER REFERENCES user_companies(id),
  role VARCHAR(50) DEFAULT 'user', -- 'admin' or 'user'
  email_verified BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Target companies (businesses users want to acquire)
CREATE TABLE target_companies (
  id SERIAL PRIMARY KEY,
  user_company_id INTEGER REFERENCES user_companies(id), -- Which acquiring company is tracking this
  company_name VARCHAR(255) NOT NULL,
  industry VARCHAR(100),
  website VARCHAR(255),
  phone VARCHAR(50),
  email VARCHAR(255),
  address TEXT,
  annual_revenue DECIMAL(15,2),
  employee_count INTEGER,
  year_established INTEGER,
  description TEXT,
  created_by INTEGER REFERENCES users(id),
  created_at TIMESTAMP DEFAULT NOW()
);

-- Primary contacts at target companies
CREATE TABLE target_contacts (
  id SERIAL PRIMARY KEY,
  target_company_id INTEGER REFERENCES target_companies(id),
  first_name VARCHAR(100) NOT NULL,
  last_name VARCHAR(100) NOT NULL,
  title VARCHAR(100),
  email VARCHAR(255),
  phone VARCHAR(50),
  is_primary BOOLEAN DEFAULT FALSE,
  notes TEXT,
  created_at TIMESTAMP DEFAULT NOW()
);

-- User sessions
CREATE TABLE user_sessions (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  session_token VARCHAR(255) UNIQUE NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);

Key Implementation Notes
Data Isolation: ALWAYS filter queries by user_company_id to ensure users only see their company's target companies
User Structure: Remember users are BUYERS tracking companies they want to ACQUIRE
Security: Hash passwords, validate inputs, use sessions properly
Database: Use Replit's built-in PostgreSQL database
UI: Keep it simple and professional - this is for business users
