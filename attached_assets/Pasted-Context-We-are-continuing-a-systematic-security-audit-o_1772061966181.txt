Context: We are continuing a systematic security audit of this multi-tenant M&A CRM. We are now fixing a dangerous escape hatch in the core tenant isolation logic.
The problem: In server/repositories/target-companies.repository.ts, the getById method contains a conditional that completely bypasses tenant scoping when userCompanyId is 0:
typescriptasync getById(id: number, userCompanyId: number): Promise<TargetCompany | undefined> {
  const [company] = await db
    .select()
    .from(targetCompanies)
    .where(
      userCompanyId === 0
        ? eq(targetCompanies.id, id)                                          // ❌ No tenant filter
        : and(eq(targetCompanies.id, id), eq(targetCompanies.userCompanyId, userCompanyId))
    );
  return company || undefined;
}
If a user's session ever has userCompanyId as 0 rather than null — through a bug in the registration flow, an edge case in session setup, or a new user who hasn't completed company assignment — this silently grants them access to any company in the database with no tenant check. This is a silent failure mode that is invisible in normal operation but catastrophic if triggered.
The fix: Remove the escape hatch entirely. The method should always enforce tenant scoping. If system admin access to any company is genuinely needed elsewhere, it must be handled explicitly in a separate named method — not via a magic zero value.
