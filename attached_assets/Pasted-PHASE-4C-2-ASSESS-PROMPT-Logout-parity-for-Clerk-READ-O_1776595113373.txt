PHASE 4C-2 ASSESS PROMPT — Logout parity for Clerk

READ-ONLY. Do not modify any files. Do not restart the server. Report findings at the end.

GOAL OF 4C-2
When CLERK_ENABLED=true and a user is authenticated via Clerk, clicking logout must clear the Clerk __session cookie in addition to the Express session cookie. Currently only the Express session is destroyed, so the user remains authenticated via Clerk cookie on next request, which presents as "logout does nothing".

When CLERK_ENABLED=false, logout behaviour must remain byte-for-byte unchanged.

ASSESSMENT TASKS

1. CONFIRM CURRENT LOGOUT FLOW
   Read client/src/components/layout/NavUser.tsx. Confirm:
   a) The logoutMutation calls POST /api/v2/auth/logout via apiRequest
   b) onSuccess redirects via window.location.href = "/login"
   c) There is no call to Clerk's signOut() anywhere in this file

2. CLERK SDK HOOK AVAILABILITY
   Read @clerk/react types or the package's dist to confirm:
   a) useClerk is exported from @clerk/react
   b) The returned object has a signOut method
   c) signOut signature — does it return a Promise, accept an optional redirectUrl or session parameter
   Do NOT guess; read the type definitions. Report the exact method signature.

3. SIGN-OUT BEHAVIOUR WHEN NO CLERK SESSION EXISTS
   Based on @clerk/react docs or source: is it safe to call signOut() when the user has no active Clerk session (i.e. flag off, no __session cookie)? Does it throw, no-op, or something else?

4. useServerConfig ACCESSIBILITY FROM NavUser
   NavUser.tsx currently imports useAuth. Confirm useServerConfig can be imported from the same @/hooks path without circular dependency issues. Just confirm the file exists at client/src/hooks/useServerConfig.ts and the export shape matches { config, clerkEnabled, isLoading, error }.

5. ORDER-OF-OPERATIONS CONSIDERATION
   Evaluate whether Clerk signOut should run before or after the Express logout POST:
   - Clerk first then Express: if Clerk signOut throws, Express session remains, user stays logged in. Failure mode observable and recoverable.
   - Express first then Clerk: if Clerk signOut throws, __session still present, next /me call re-authenticates via Clerk path. Silent failure — logout appears to work briefly then user is back.
   Recommend one based on this reasoning, or propose a third option.

6. THE APIREQUEST CSRF QUIRK
   queryClient.ts attaches x-csrf-token to non-GET requests only if csrfToken is set. Confirm that csrfToken is definitely set by the time logout runs (i.e. the csrf fetch in useAuth has completed). If not, logout may fail validation. Worth noting for 4C-2 or deferring.

7. REDIRECT TARGET UNDER CLERK FLAG ON
   NavUser currently redirects to /login on logout success. When CLERK_ENABLED=true, should the redirect target change to /sign-in, or stay /login (which is always registered regardless of flag)? Consider: in the flag-on state a freshly-logged-out user visiting /login just sees the old session login form, which is confusing but functional. /sign-in is only registered when flag on. Recommend one.
