Enforce role-based permissions on the routes that need them. The infrastructure (rolesService.checkPermission, UserWithPermissions, the userRoles table) already exists — we are just wiring it in.

1. Create a helper middleware factory in server/middleware/auth.ts called requirePermission. It should take a permission key (keyof UserRole) and return a middleware that:
- Gets userId from session
- Calls rolesService.checkPermission(userId, permission)
- If true, calls next()
- If false, returns 403: { success: false, message: 'You do not have permission to perform this action', code: 'FORBIDDEN' }
- If the user is isSystemAdmin (check via a DB lookup), always pass through regardless of role permissions

2. Apply requirePermission to these routes in server/routes/index.ts:

Financial data routes — wrap with requirePermission('canViewFinancials'):
app.use('/api/v2/financial-data', isAuthenticated, requirePermission('canViewFinancials'), financialDataRoutes)

Team management routes — wrap with requirePermission('canManageUsers'):
app.use('/api/v2/team', isAuthenticated, requirePermission('canManageUsers'), teamRoutes)
Note: keep publicTeamRoutes (invitation acceptance) WITHOUT the permission check — those are public.

Expert analysis trigger routes — wrap with requirePermission('canViewFinancials'):
app.use('/api/v2/expert-analysis', isAuthenticated, requirePermission('canViewFinancials'), analysisTriggerLimiter, expertAnalysisRoutes)

Reports routes — wrap with requirePermission('canAccessAnalytics'):
app.use('/api/v2/reports', isAuthenticated, requirePermission('canAccessAnalytics'), reportsRoutes)

3. All other routes remain as they are — this is targeted, not a blanket change.

4. Update the /api/v2/auth/me response in server/routes/auth.routes.ts to also return the user's permissions object so the frontend knows what the current user can and cannot do. Fetch this via rolesService.getUserWithPermissions(userId) and include the permissions field in the response alongside the existing user and company fields.
