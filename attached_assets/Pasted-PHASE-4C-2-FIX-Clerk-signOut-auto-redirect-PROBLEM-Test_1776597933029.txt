PHASE 4C-2 FIX — Clerk signOut auto-redirect

PROBLEM
Tested flag-on logout: __session cleared, but user lands on /login (Valoxi session login) rather than /sign-in (Clerk UI). Express session sid is also not cleared — a fresh empty sid appears instead. Root cause: Clerk's signOut() performs its own browser navigation to the Clerk Dashboard "after sign-out" URL (configured as /login earlier), which starts before our await resolves. This cancels the await, so apiRequest("POST", "/api/v2/auth/logout") never fires and onSuccess never fires. The fresh sid is express-session issuing a new uninitialised session on the /login page load.

FIX
Use the callback form of signOut so Express logout runs as part of the sign-out flow, and pass explicit redirectUrl to override the Dashboard config. The callback runs after __session is cleared but before Clerk navigates, so both cookies are gone before the redirect.

STEP 1 — Modify client/src/components/layout/NavUser.tsx

Find the current logoutMutation block, which looks like this:

  const logoutMutation = useMutation({
    mutationFn: async () => {
      if (clerkEnabled) {
        await signOut();
      }
      await apiRequest("POST", "/api/v2/auth/logout");
    },
    onSuccess: () => {
      window.location.href = clerkEnabled ? "/sign-in" : "/login";
    },
    onError: () => {
      toast({
        title: "Error",
        description: "Failed to logout. Please try again.",
        variant: "destructive",
      });
    },
  });

Replace with:

  const logoutMutation = useMutation({
    mutationFn: async () => {
      if (clerkEnabled) {
        // Callback form: runs after Clerk clears __session, before Clerk navigates.
        // Express logout inside the callback ensures sid is destroyed before redirect.
        // Explicit redirectUrl overrides the Clerk Dashboard "after sign-out" config.
        await signOut(
          async () => {
            await apiRequest("POST", "/api/v2/auth/logout");
          },
          { redirectUrl: "/sign-in" }
        );
        // Clerk handles the browser navigation after the callback resolves.
        // Code below this line will not execute in the flag-on path.
      } else {
        await apiRequest("POST", "/api/v2/auth/logout");
      }
    },
    onSuccess: () => {
      // Only reached in the flag-off path. Flag-on navigation is handled by Clerk.
      if (!clerkEnabled) {
        window.location.href = "/login";
      }
    },
    onError: () => {
      toast({
        title: "Error",
        description: "Failed to logout. Please try again.",
        variant: "destructive",
      });
    },
  });

Rest of the component is unchanged.

STEP 2 — Type check

Run: npm run check

The two-argument overload of signOut is:
  signOut(signOutCallback?: () => void | Promise<any>, options?: { sessionId?: string; redirectUrl?: string }): Promise<void>

Our call matches: first arg is an async callback, second arg is an options object with redirectUrl. Expect zero new errors.
