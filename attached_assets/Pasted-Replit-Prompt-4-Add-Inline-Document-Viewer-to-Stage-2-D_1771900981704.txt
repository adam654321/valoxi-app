Replit Prompt 4: Add Inline Document Viewer to Stage 2 DD (Both Views)
## Context

The Stage 2 Due Diligence views show linked and uploaded documents as plain-text filenames with no way to view their content. We need to integrate the existing `DocumentViewer` component to allow inline document viewing (PDFs, images, text files rendered in-browser). The `DocumentViewer` is already used in the Stage 1 portal view and works with both authenticated and public file endpoints.

Key architecture details:
- `DocumentViewer` lives at `client/src/components/document-viewer/DocumentViewer.tsx`
- Its props interface is in `client/src/components/document-viewer/types.ts`: `{ document, isOpen, onClose, onDownload, publicFileBaseUrl?, hideAnalysis? }`
- The `DocumentPreview` sub-component uses `document.fileType` to determine if inline preview is possible (PDF, images, text) and constructs URLs as `publicFileBaseUrl/{id}/view` (portal) or `/api/v2/files/{id}/view` (internal)
- The `document.id` must be the **documents table ID** (not the ddRequirementDocuments link ID)
- Public file endpoints: `/api/v2/public/documents/:id/view` and `/api/v2/public/documents/:id/download`
- Authenticated file endpoints: `/api/v2/files/:id/view` and `/api/v2/files/:id/download`
- The `hideAnalysis` prop hides Analysis and Webhook JSON tabs (added in earlier change)
- Stage 2 DD does NOT need analysis tabs — analysis is only relevant for Stage 1

The `LinkedDocument` interface in both files has:
- `id` — this is the **ddRequirementDocuments junction table ID** (NOT the document ID)
- `documentId` — the actual documents table ID (for buyer_linked docs)
- `externalSubmissionId` — for seller_uploaded docs
- `filename`, `fileType`, `fileSize`

**Critical**: When constructing the document object for the viewer, use `doc.documentId` (not `doc.id`) as the document ID. For seller_uploaded documents, the document is also inserted into the `documents` table during submission, so `doc.documentId` should be populated. If `doc.documentId` is null, fall back to `doc.externalSubmissionId` — but note this may not resolve to a viewable file via the standard endpoints.
