Context
Continuing the Deal Modeller build. Step 6 created the three new database tables (deal_models, deal_model_adjustments, deal_model_funding_lines). Now we're building the service that reads expert analysis results and financial data, then populates a new deal model with sensible defaults and suggested adjustments.
This is the bridge between the Expert Analysis engine and the Deal Modeller. The expert engine already produces structured JSON with add-backs, deductions, valuation multiples, deal structures, and financial metrics. This service maps that data into our new tables.
Step 7 — Build Deal Model Data Mapping Service
Before writing any code, read these files carefully to understand the data structures you'll be mapping from:

server/prompts/stage2-qoe-expert-prompt.ts — Look at the JSON output structure it asks for. You need the add_backs[], deductions[], director_salary_analysis, and adjusted_ebitda fields.
server/prompts/stage2-valuation-expert-prompt.ts — Look for the ebitda_multiple_valuation with sector multiple range and ev_to_equity_bridge fields.
server/prompts/stage2-deal-structure-prompt.ts — Look for the structures[] array, specifically the balanced/moderate structure's consideration object.
server/prompts/stage2-financial-expert-prompt.ts — Look for yearly_metrics with revenue, EBITDA, margins per year.
server/services/expert-analysis.service.ts — Understand how expert results are stored. Each expert type's output goes into expert_analysis_results.analysisData as JSON, keyed by expertType (e.g. 'qoe', 'valuation', 'deal_structure', 'financial').
shared/schema/deal-models.ts — The tables you're populating (just created in Step 6).
shared/schema/financials.ts — The balanceSheets, fixedAssetsRegister, incomeStatements tables that provide asset values for funding line seeds.

Now create server/services/deal-model-mapping.service.ts
This service should export a class DealModelMappingService (following the pattern of other services in the codebase) with one main public method:
typescriptasync createDealModelFromExperts(
  targetCompanyId: number,
  createdBy: number,
  userCompanyId: number,
  modelName?: string
): Promise<DealModel>
This method should:

Fetch the latest completed expert analysis results for the target company — get all expert types where status = 'completed'. If no completed QoE or valuation expert results exist, throw a BadRequestError saying expert analysis must be completed first.
Parse the expert JSON data from analysisData for each expert type. Be defensive — wrap all JSON access in try/catch, use optional chaining, and provide sensible defaults if fields are missing. The expert data is AI-generated and may not always have every field.
Create the deal model record with these mappings:
From Valuation Expert → deal_models fields:

analysisData.ebitda_multiple_valuation.sector_multiple_range.low → multipleLow
analysisData.ebitda_multiple_valuation.sector_multiple_range.high → multipleHigh
analysisData.ebitda_multiple_valuation.selected_multiple → ebitdaMultiple
analysisData.ev_to_equity_bridge.plus_cash → plusExcessCash
analysisData.ev_to_equity_bridge.minus_long_term_debt → minusPrimaryDebt
analysisData.ev_to_equity_bridge.minus_director_loans → minusOtherDebt
analysisData.ev_to_equity_bridge.minus_working_capital_adjustment → minusWorkingCapitalAdj

From Deal Structure Expert → deal_models consideration fields:
Find the "balanced" or "moderate" structure from analysisData.structures[] (match on name containing "balanced" or "moderate", case-insensitive — do NOT use array index). Map:

consideration.upfront_cash → upfrontCash
consideration.deferred or consideration.deferred_amount → deferredAmount
consideration.deferred_schedule → deferredTerms
consideration.earnout_maximum → earnoutMaximum
consideration.earnout_metric → earnoutMetric
consideration.earnout_period_months → earnoutPeriodMonths
consideration.retention_escrow → retentionEscrow

Set defaults for fees: feeLegalDdPercent: '2.5', feeAccountingDdPercent: '1.5', feeBrokerPercent: '2.0', feeLoanArrangementPercent: '1.0', feeDealMakerPercent: '5.0'.
Store the raw expert data and financial data as snapshots (expertDataSnapshot, financialDataSnapshot).
Create adjustment records from QoE Expert:
Add-backs: For each item in analysisData.add_backs[]:

item or description → description
category → category (map to our category enum — use best match, default to one_off_cost if unmappable)
amount → amount
justification or reasoning → expertReasoning
confidence → confidence
Set adjustmentType: 'add_back', status: 'suggested', sourceExpert: 'qoe'
Link sourceExpertResultId to the QoE expert result record

Deductions: Same pattern for analysisData.deductions[], with adjustmentType: 'deduction'.
Director salary adjustments: From analysisData.director_salary_analysis.directors[]:

If current_salary > market_rate → create add_back with category owner_salary_excess, amount = difference
If current_salary < market_rate → create deduction with category replacement_salary, amount = difference


Create funding line seeds from financial data:
Fetch the latest balanceSheets and fixedAssetsRegister for the target company.

If tradeDebtors exists → create a receivables_finance line with assetBaseValue = tradeDebtors, ltvPercent = 80, interestRate = 4.5, termMonths = 1 (revolving), isActive = false (user opts in)
If plant/machinery + vehicles exist in fixedAssetsRegister → create an asset_finance line with assetBaseValue = sum of plantMachineryNetBookValue + vehiclesNetBookValue, ltvPercent = 60, interestRate = 6.0, termMonths = 60, isActive = false
If property exists → create a property_finance line with assetBaseValue from propertyNetBookValue, ltvPercent = 65, interestRate = 5.0, termMonths = 240, isActive = false
Always create a cash_equity line with amountUsed = 0, isActive = true (this is the funding gap / cash to introduce)



Export a singleton instance: export const dealModelMappingService = new DealModelMappingService();
Important implementation notes:

Use the existing db instance from server/db.ts for database access
Use Drizzle query patterns consistent with the existing repositories
All decimal values from expert JSON should be converted to strings for Drizzle decimal columns
Log the mapping process with console.log using the prefix [DEAL_MODEL_MAPPING] (matching the [EXPERT:...] and [GEMINI_...] logging patterns in the codebase)
If optional expert data is missing (e.g. no deal structure expert), skip those fields gracefully — don't fail the whole model creation
