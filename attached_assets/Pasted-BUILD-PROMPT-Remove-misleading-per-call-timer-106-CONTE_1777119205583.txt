BUILD PROMPT — Remove misleading per-call timer (#106)

CONTEXT
Three production UI surfaces render a timer that displays the
duration of a single Gemini call rather than the elapsed time of
the user-perceived operation. Confirmed via assessment 25/04/2026.
Examples: "7.7s" displayed against an Asset Register analysis that
took 45s end-to-end; "12.2s" displayed in an Operational Report
header inside a pipeline that took 230s. Generates support queries.
Action log #106: pure UI deletion, zero logic change.

The companion timestamp "Processed: <date>" in AnalysisDisplay.tsx
is the analysis-row creation date, NOT the misleading timer, and
stays in place. The processingTime database column, server-side
computation in expert-analysis.service.ts and gemini-* services,
DocumentAnalysisResult.processingTime field, and ExpertResult
.processingTime field all stay untouched. We delete three JSX
render blocks and nothing else.

EXPLICITLY OUT OF SCOPE

- client/src/pages/webhook-test.tsx (line 285)
