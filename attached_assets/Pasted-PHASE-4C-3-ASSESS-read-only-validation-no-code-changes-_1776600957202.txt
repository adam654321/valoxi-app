CLERK_USER_NOT_LINKED (403, usually a brief webhook race after Clerk signup) and CLERK_USER_INACTIVE (401, soft-deleted or disabled Valoxi user). Today both failure modes dump the user on the Login page with no explanation. We need clear UI for each.

PLAN
All changes are frontend. Zero backend touch. Zero changes to queryClient.ts.

client/src/hooks/useAuth.ts — replace the current getQueryFn({ on401: "returnNull" }) with a custom inline queryFn scoped only to the /api/v2/auth/me query. Behaviour:

If response.ok, return await res.json().
Else read body as text, try JSON.parse.
If parsed.code or parsed.error equals CLERK_USER_NOT_LINKED or CLERK_USER_INACTIVE, throw new Error(parsed.message) with err.status = res.status and err.code = the matched value.
Else if res.status is 401, return null. Preserves today's unauthenticated behaviour exactly.
Else throw with err.status and the message.
Add retry config on the useQuery call: retry returns true only when error.code is CLERK_USER_NOT_LINKED and failureCount is less than 3. retryDelay returns 800, 1500, 2000 for attempts 0, 1, 2. Any other error, no retry.
Expose authError on the return object, typed as 'CLERK_USER_NOT_LINKED' | 'CLERK_USER_INACTIVE' | null, read from (error as any)?.code ?? null.


client/src/App.tsx — inside the Router function, after the useAuth and useServerConfig hooks and after the authLoading/configLoading check, but before the !isAuthenticated early return, add two new branches:

if (authError === 'CLERK_USER_NOT_LINKED') return the AccountSetupPending page wrapped in Suspense with the existing LoadingSpinner fallback.
if (authError === 'CLERK_USER_INACTIVE') return the AccountInactive page wrapped in Suspense.
Both must be lazy-imported the same way the other auth pages are lazy-imported at the top of App.tsx.


client/src/pages/auth/account-setup-pending.tsx — new file. Renders a centred card matching the sign-in page styling with a spinner and copy along the lines of "Setting up your account..." and a short paragraph explaining this usually resolves in a few seconds. Button labelled "Retry now" that calls queryClient.invalidateQueries({ queryKey: ['/api/v2/auth/me'] }). Below that, a muted-tone "Still stuck? Contact support" mailto link. No destructive actions on this page.
client/src/pages/auth/account-inactive.tsx — new file. Renders a centred card with copy "This account is no longer active." Button labelled "Sign out" that does await apiRequest("POST", "/api/v2/auth/logout") first and then await signOut({ redirectUrl: "/sign-in" }) from useClerk. Exactly the pattern in client/src/components/layout/NavUser.tsx logoutMutation. Plus a "Contact support" mailto link.
