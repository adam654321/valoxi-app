We are continuing Stage 3. Step 2: the AI Explain feature and Deal Metrics Snapshot storage.
Context:

The platform has an expert analysis system that produces commercial due diligence reports with metrics, risk scores, EBITDA adjustments, and valuations
Users — especially first-time acquirers on the Core tier — do not understand many of the financial metrics they see
The AI Explain feature adds "What does this mean?" buttons next to key metrics, calling Gemini to explain the metric in plain English in the context of the specific deal
Deal Metrics Snapshots capture a point-in-time record of key deal metrics when a model is saved or analysis is completed — used for audit trail and future benchmarking

Add a dealMetricsSnapshots table to shared/schema/deal-models.ts:
Columns:

id serial PK
userCompanyId integer FK → user_companies.id NOT NULL
targetCompanyId integer FK → target_companies.id NOT NULL

Task 3 — AI Explain endpoint:
Add POST /api/v2/explain/metric to a new route file server/routes/explain.routes.ts:

Requires isAuthenticated and requireActiveSubscription
Rate limited — use the existing analysisTriggerLimiter or create a new limiter of 20 requests per user per hour (check the existing rate limiter setup and follow the same pattern)
Request body: { metricKey: string, metricValue: string | number, context: { companyName: string, sector: string, revenue?: number, adjustedEbitda?: number } }
Calls Gemini (use the existing gemini-client.ts) with a carefully constructed prompt
Returns { explanation: string } — plain English explanation, 2–4 sentences max

The Gemini prompt must include these guardrails — add them as a system instruction:

You are a financial education assistant helping a business acquirer understand a metric in their deal analysis
Explain the metric in plain English, in the context of the specific company provided
Do not give investment advice or recommendations
Do not say whether the deal is good or bad
Keep your explanation to 2–4 sentences
End with one sentence explaining what a typical range looks like for a UK SME in this sector

Register the route in server/routes/index.ts under /api/v2/explain with isAuthenticated and requireActiveSubscription.
