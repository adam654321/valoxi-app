Reads the Authorization: Bearer <jwt> header, verifies, looks up clerk_user_id in users table, populates req.session.userId + req.session.userCompanyId for downstream compatibility.
Modify server/middleware/auth.ts — isAuthenticated becomes dual-path:

If CLERK_ENABLED=true AND request has Authorization: Bearer header → try Clerk verification
If Clerk succeeds: populate session fields, call next()
If Clerk fails or header absent → fall back to existing session check
If both fail → 401


Modify server/middleware/csrf.ts — skip CSRF when request was Clerk-authenticated (the JWT itself is the anti-CSRF protection — it's a bearer token that can't be sent cross-site by a browser unless attacker already has it). We'll mark Clerk-auth'd requests via req.clerkAuthenticated = true and short-circuit in validateCsrfToken.
Wire clerkMiddleware() into Express — add at the app level in server/routes.ts so it runs early and populates req.auth on every request. Harmless if no token present — it just leaves req.auth.userId as null.
Test via a protected endpoint — flip CLERK_ENABLED=true, obtain a Clerk session token from a test signup, hit /api/v2/auth/me with the Bearer header, verify it returns a 401 (because we have no clerk_user_id matched in the DB yet — that's expected until 4B-3's webhook handlers link accounts).
