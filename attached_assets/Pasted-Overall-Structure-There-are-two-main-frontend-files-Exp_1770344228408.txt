Overall Structure

There are two main frontend files:

ExpertAnalysisDashboard.tsx - The main orchestration component (the "dashboard")
ExpertReportViews.tsx - Individual report view components for each expert type
The dashboard is embedded inside the target company detail page, appearing as a tab/section within the company view.

Expert Configuration

Each expert is defined in a static config object (EXPERT_CONFIG) with:

Label (display name)
Icon (from Lucide React)
Layer number (determines visual grouping and execution order)
Dependencies (which other experts must complete first)
The 10 experts are:

Expert	Layer	Depends On
Data Quality	0	None
Screening	0	Data Quality
Financial	1	None
Operational	1	None
Risk	1	None
Quality of Earnings	2	Financial, Operational
Sector	2	Financial, Operational, Risk
Valuation	3	Financial, Operational, Risk, QoE, Sector
Deal Structure	3	Financial, Risk, Valuation
Synthesis	4	All others
Two-Phase Layout

The dashboard visually splits into two phases:

Phase 1 (Screening): Shows Data Quality and Screening as a prerequisite step. These must complete before Phase 2 can begin.
Phase 2 (Expert Deep Dive): Shows Layers 1-4 in separate visual sections, each with a heading like "Layer 1: Foundation Analysis (Parallel)". Cards are arranged in grids (3 columns for Layer 1, 2 columns for Layer 2, etc.).
Expert Cards

Each expert is rendered as a clickable card showing:

The expert's icon and name
A status icon (checkmark for success, X for failed, spinner for running, clock for pending, lock for locked)
A status badge (colored label: green "Complete", red "Failed", blue "Running", yellow "Pending")
A RAG badge if complete (GREEN / AMBER / RED)
A score (out of 100) and confidence percentage
Cards are visually "locked" (greyed out, non-clickable) if their dependencies haven't completed yet
Dependency Checking

A checkDependencies function looks at each expert's dependsOn list and checks whether all those prerequisite experts have status "success". If not, the card is rendered in a disabled/locked state.

Data Fetching

Uses TanStack React Query polling the endpoint /api/v2/expert-analysis/{companyId}/results every 5 seconds
The response includes phase1Results and phase2Results arrays, plus overall progress and pipelineStatus
A progress bar at the top shows overall completion percentage
Triggering the Pipeline

A "Start Expert Deep Dive" button appears after Phase 1 completes with a PROCEED recommendation
This fires a POST to /api/v2/expert-analysis/{companyId}/trigger-pipeline
The button is disabled while running or if screening recommended NO-GO
Detailed Report Views (Dialog)

When you click a completed expert card, a modal dialog opens with a scrollable detailed report. The dialog renders a different report component depending on the expert type:

ScreeningReportView - Recommendation badge, executive summary, screening dimensions with individual scores, key strengths, critical concerns, due diligence focus areas
DataQualityReportView - Data quality metrics and issues
FinancialReportView - Yearly financial tables, CAGR metrics, cost structure, YTD period indicators with annualization notes
OperationalReportView - Operational metrics and analysis
RiskReportView - Risk assessment details
QoEReportView (Quality of Earnings) - Earnings quality analysis
SectorReportView - Sector/market analysis
A generic fallback view for Valuation, Deal Structure, and Synthesis that renders whatever JSON structure the AI returns
Visual Design Patterns

Uses shadcn Card, Badge, Dialog, ScrollArea, Progress, Table, Separator components throughout
RAG color coding: Green = good, Amber = caution, Red = concern
Financial figures are color-coded (green for positive trends, red for negative)
SectionCard helper wraps report sections with an icon and title
Tables with horizontal scroll for financial data across multiple years
whitespace-pre-wrap on narrative text to preserve AI-generated formattin
