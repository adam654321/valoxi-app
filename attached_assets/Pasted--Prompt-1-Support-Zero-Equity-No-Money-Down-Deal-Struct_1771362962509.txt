# Prompt 1: Support Zero-Equity (No Money Down) Deal Structures

## Context

In the Value Creation module, three sections (Returns Analysis, Sensitivity Analysis, and Exit Modelling & Scenario Comparison) are currently hidden when `entryEquity === 0` because of `entryEquity <= 0` guard conditions. This is wrong — a fully debt-funded deal with zero equity is a valid "no money down" structure and the module should support it.

This is the first of four prompts redesigning the Value Creation Modeller. It must be applied first because the remaining prompts depend on all 7 sections being visible and testable.

---

## Files to Change

### 1. `client/src/components/target-company/ValueCreationModeller.tsx`

The three render guards and two `useMemo` calculations use `entryEquity <= 0` as a bail-out condition. Change these so that sections render when `entryEquity === 0` as long as the deal has active funding lines (i.e. the deal is actually funded, just fully with debt). The guards should only block rendering when there are NO active funding lines at all — meaning no deal structure exists yet.

**Add a helper:**

```typescript
const hasActiveFunding = fundingLineInputs.some(f => f.isActive);
```

**Fix these three `useMemo` hooks** — change the guard from `entryEquity <= 0` to `!hasActiveFunding`:

1. `returnMetrics` useMemo — currently returns null if `entryEquity <= 0`
2. `sensitivityData` useMemo — same issue  
3. `scenarioComparison` useMemo — same issue

In each case, replace:
```typescript
if (... || entryEquity <= 0) return null;
```
With:
```typescript
if (... || !hasActiveFunding) return null;
```

### 2. `shared/calculators/value-creation.calc.ts`

The `calculateReturns` function will have division-by-zero issues when `entryEquity === 0`. Review the full function and add early handling for the `entryEquity === 0` case:

- **MOIC**: `totalReturn / entryEquity` → infinity. For a no-money-down deal, MOIC is technically infinite. Return `Infinity` and let the UI display `∞`.
- **IRR**: The IRR solver uses the initial equity outflow as the first cash flow (negative). If that's zero, the solver will either fail or produce nonsensical results. For a zero-equity deal, IRR is mathematically undefined (infinite return on zero invested). Return `Infinity` or a sentinel value.
- **Payback period**: If no equity was invested, payback is effectively instant (0 years). Return `0`.

The exit equity, debt paydown, cash distributions, and value bridge calculations should still work normally — those are based on EV and debt, not equity invested.

Add handling near the top of `calculateReturns`:

```typescript
const isZeroEquity = entryEquity === 0;

// MOIC
const moic = isZeroEquity ? Infinity : totalReturn / entryEquity;

// Payback
let paybackPeriodYears = isZeroEquity ? 0 : holdYears;
// (skip the cumulative cash loop if zero equity — payback is instant)

// IRR cash flows
const cashFlows: number[] = isZeroEquity ? [0] : [-entryEquity];
// ... rest of cash flow building stays the same
const irr = isZeroEquity ? Infinity : calculateIRR(cashFlows);
```

### 3. `client/src/components/value-creation/ReturnsAnalysisSection.tsx`

The display already handles some edge cases (e.g. `irrDisplay` checks for NaN/Infinity). Extend this:

- If MOIC is `Infinity`, display `∞` with green colouring
- If IRR is `Infinity`, display `∞` with green colouring
- If payback is `0`, display `"Instant"` or `"0 yrs"`
- **Add a small badge** near the KPI cards when it's a no-money-down deal so the user understands why metrics show infinity:

```tsx
{entryEquity === 0 && (
  <Badge variant="outline" className="text-[10px]">
    No equity invested — fully debt funded
  </Badge>
)}
```

This requires passing `entryEquity` as a new prop to `ReturnsAnalysisSection` (or deriving it from `metrics.entryEquity` which is already on `ReturnMetrics`).

### 4. `client/src/components/value-creation/ExitScenarioSection.tsx`

Same display handling for the MOIC and IRR values shown in:
- The bear/base/bull comparison table (Scenario Comparison sub-tab)
- The three exit valuation cards (Exit Valuation sub-tab)

The existing `formatIrr` function already returns `'N/A'` for `!isFinite(v)`. Change this to return `'∞'` instead when the value is `Infinity` (as opposed to `NaN`):

```typescript
const formatIrr = (v: number) => {
  if (isNaN(v)) return 'N/A';
  if (!isFinite(v)) return '∞';
  if (v > 10) return 'N/A';
  return `${(v * 100).toFixed(1)}%`;
};
```

Similarly for MOIC display, handle `Infinity`:
```typescript
{isFinite(ret.moic) ? `${ret.moic.toFixed(2)}x` : '∞'}
```

### 5. `client/src/components/value-creation/SensitivityAnalysisSection.tsx`

The tornado chart and heatmap use total return as the output variable. These should still work fine with zero equity since they're based on projections not equity ratios. But verify the break-even calculations in the calculator don't divide by equity anywhere — they currently don't (they check DSCR and FCF which are debt-based), but confirm.

## Do NOT Change

- The P&L Projections, Synergies, Capital Deployment, or Cash Flow Waterfall sections — these already work fine regardless of equity
- The fundamental calculation logic for projections, debt schedules, or waterfall

## Test Scenarios

1. **Deal with £100K equity + £400K debt:** All 7 sections render with normal metrics. No behavioural change from current.

2. **Deal with £0 equity + £500K debt (no money down):** All 7 sections render. IRR and MOIC show `∞`. Payback shows `Instant` or `0 yrs`. "No equity invested — fully debt funded" badge visible in Returns Analysis. Exit equity, value bridge, and cash flow calculations work normally.

3. **Deal with no funding lines at all:** Returns, Sensitivity, and Exit sections show nothing (or empty state once Prompt 2 adds those). This is the correct behaviour — there's no deal structure to analyse.

4. **Sensitivity analysis with zero equity:** Tornado chart and heatmap should still function. Break-even calculations should work since they test DSCR and FCF thresholds, not equity-based metrics.
