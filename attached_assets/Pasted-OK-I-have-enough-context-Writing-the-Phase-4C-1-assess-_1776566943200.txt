Step 2. Backend public config endpoint.
Create a tiny GET /api/v2/public/config endpoint that returns server-side config the frontend needs to know. Initially just clerkEnabled. Public, no auth.
Approach: add to existing public routes or create new server/routes/public.routes.ts. Recommend the minimum-blast-radius approach given the route registration patterns in server/routes/index.ts.

Register without middleware (public endpoint, no session or CSRF needed).
Step 3. Frontend config hook.
Create client/src/hooks/useServerConfig.ts. Uses react-query to fetch /api/v2/public/config once on mount, caches the result. Returns { clerkEnabled, isLoading }.
Example shape:
export function useServerConfig() {
const { data, isLoading } = useQuery<{ clerkEnabled: boolean }>({
queryKey: ["/api/v2/public/config"],
queryFn: async () => {
const res = await fetch("/api/v2/public/config");
return res.json().then(j => j.data ?? j);
},
staleTime: Infinity,
retry: 1,
});
return { clerkEnabled: data?.clerkEnabled ?? false, isLoading };
}
Used in the Router component alongside useAuth.
