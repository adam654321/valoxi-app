Step 1 Prompt for Replit

I'm splitting the monolithic shared/schema.ts (1,200+ lines) into domain modules. In this first step, I want to create the shared/schema/ directory and build the two foundational domain files that everything else depends on: core.ts and deals.ts. The original shared/schema.ts must remain untouched for now — we're just creating the new files alongside it and verifying they compile.

Target structure after all 3 steps (for context):
shared/
  schema/
    core.ts          ← users, companies, sessions, roles, invitations
    deals.ts         ← target companies, contacts, pipeline, activities, notes
    documents.ts     ← document storage, analysis, AI pipeline
    portal.ts        ← external portal, submissions, chase-ups
    financials.ts    ← P&L, balance sheets, staff, assets, valuations
    dashboard.ts     ← dashboard widgets, alerts, composite types
    relations.ts     ← ALL Drizzle relation definitions
    index.ts         ← barrel file re-exporting everything
  schema.ts          ← (Step 3) becomes just: export * from './schema/index'
Why relations go in a separate file: Relations like usersRelations reference tables from multiple domains (e.g., many(activities) from deals, many(expertAnalysisResults) from documents). If those relations lived in core.ts, it would need to import from deals.ts and documents.ts, while they both import from core.ts — creating circular imports. A single relations.ts file that imports all tables avoids this entirely.
