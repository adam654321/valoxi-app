Stripe API v2026 coupon migration — FINAL BUILD. Make the exact changes below in the order given. Do not deviate.

Context: Stripe's March 2025 API changes removed coupon and discounts parameters from the Customer object entirely. Coupons now attach at Subscription creation time (via Checkout Session discounts array) or on existing subscriptions (via stripe.subscriptions.update discounts). Prior cycle's attempt to use discounts on stripe.customers.update also returned 400. This build migrates to the correct structural pattern.

Four changes across two files:

  CHANGE A: server/routes/billing.routes.ts (/checkout) — delete the stripe.customers.update block entirely
  CHANGE B: server/routes/billing.routes.ts (/checkout) — inject discounts into checkoutParams
  CHANGE C: server/cron/billing.cron.ts — swap stripe.customers.update for stripe.subscriptions.update, gate on stripeSubscriptionId
  CHANGE D: server/routes/billing.routes.ts (/upgrade) — resolve and inject coupon on plan-swap subscription update

Verified pre-conditions (from prior assess):
- SDK v20.4.0 natively types discounts on both checkout.sessions.create and subscriptions.update (no as any needed)
- promoCodeService is already imported at top of billing.routes.ts (line 8)
- stripe.subscriptions.update({ discounts: [...] }) does NOT trigger prorations or invoices on its own
- PATH A (5D New Member terminal flip) in the cron correctly bypasses the coupon block (no Stripe sub, status='trialing'), so Change C only affects PATH B/C users
