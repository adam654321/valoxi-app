Function logic:
a) Compute window: now minus 24 hours, expressed as Unix timestamps for Stripe (gte for the start, no end needed since now is implicit)

c) Call stripe.events.list({ delivery_success: false, limit: 100, created: { gte: startUnix } }). Paginate via starting_after if has_more is true. Cap pagination at 5 pages defensively (500 events) and log a warning if cap is hit.
d) If failureCount === 0, log [billing-cron] No webhook failures in last 24h and return. No email sent on zero failures.
e) If failureCount > 0, build a plain text email body listing each failed event:

event id
event type
created timestamp (ISO 8601 UTC)
pending_webhooks count

Subject line: [Valoxi] N Stripe webhook failure(s) in last 24h
Where N is the count.
Body opening line: One sentence stating the count and the window. Then a blank line. Then the event list, one event per line, comma separated fields. Then a blank line. Then a closing line pointing to the Stripe dashboard webhook page for investigation.
f) Send via emailApiService using the same call shape used by existing methods in this file. Plain text, no HTML, no renderBrandedEmail. Recipient is config.alertEmail. From address default (noreply@send.valoxi.ai).
g) Log [billing-cron] Sent webhook failure alert for N event(s) to <recipient> on success. console.error on send failure but do not throw — let the cron exit cleanly so the next day's run still fires.
