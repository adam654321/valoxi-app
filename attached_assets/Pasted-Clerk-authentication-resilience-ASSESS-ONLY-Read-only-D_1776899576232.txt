10. Proposed solution analysis
    Based on the findings from 1–9, propose specific changes per failure mode.

    A. FAILURE MODE — Clerk loop on wrong password:
       - Current: Clerk catches the error, user can retry, but if they've been in the wrong state for a while the cookie is stuck.
       - Proposed: add a "Start over" escape button rendered alongside Clerk that calls clerk.signOut() + window.location.reload().
    
    B. FAILURE MODE — Clerk loop on non-existent account during sign-up:
       - Current: Clerk creates an account, our backend webhook may fail silently, user is trapped in "signed in with Clerk, no Valoxi account".
       - Proposed: (i) gate /sign-up behind invitation token validation (accept-invitation flow sets a one-time signup token), (ii) on Clerk user.created webhook, verify invitation context and either create Valoxi user OR immediately revoke the Clerk session and redirect the user to the "access by invite" login page.

    C. FAILURE MODE — Wrong email on invite acceptance:
       - Current: error message unclear, button broken.
       - Proposed: explicit "This email does not match any invitation in our records. The invitation was sent to: [masked email]" with "Contact support" as a real mailto: link.

    D. FAILURE MODE — Logout 404:
       - Current: inconsistent behaviour.
       - Proposed: audit existing logout path, ensure it (i) calls Clerk signOut() (ii) hits server /logout to destroy Express session (iii) redirects to /sign-in. If /logout 404s, the server route is missing or mounted incorrectly.

    E. FAILURE MODE — Session cookie trap:
       - Current: Clerk stores an incomplete session cookie that blocks re-entry.
       - Proposed: on any /sign-in mount, detect if there's a session cookie but no active Clerk user; if so, force clerk.signOut() before rendering the Clerk component.
