CONTEXT
Third attempt at the 5D New Member free-period upgrade credit fix. Root cause established: the /checkout handler is re-entrant-unsafe. On a second call (most likely a double-click of the Confirm Upgrade button, which is only gated on upgradeMutation.isPending not checkoutMutation.isPending), the credit block short-circuits (coupon already set) but the trial-extension block fires because trialEndsAt is still populated in the DB and hasFreeMonthState evaluates to false (freeMonthsTotal is now 0 after the first call's DB write).

Evidence from Replit's diagnostic script (this session): Stripe sub sub_1TPPw72N2rRCsCfripetkJUK has trial_end exactly 183 days after creation, matching remainingDays computed from trialEndsAt. No other code path sets trial_period_days. Codebase grep confirmed one hit, in the gated block.

Fix has two parts:
  Part 1 (server, the real fix): clear trialEndsAt and trialEnd in both DB writes inside the /checkout credit block. This makes the trial-extension guard's existingSub?.trialEndsAt check alone block the second call, even when hasFreeMonthState has become false.
  Part 2 (client, defense in depth): gate the Confirm Upgrade button on checkoutMutation.isPending as well as upgradeMutation.isPending, so double-clicks can't trigger a second /checkout call in the first place.
