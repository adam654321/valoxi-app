PROMPT 5 — Three new routes
We are building an offline document delivery flow for Valoxi. Currently offer letters and HoTs can only be sent via the seller portal. We are adding three new backend routes to support: creating an offline document record, downloading it as a Word file with a physical signature block, and manually updating its status when the seller responds outside the portal. The buildPhysicalSignatureBlock function has already been added to document-html-builders.ts and the html-to-docx package is already installed. In server/routes/deal-document.routes.ts first add buildPhysicalSignatureBlock to the existing import from ../utils/document-html-builders so it sits alongside buildNdaHtml, buildOfferLetterHtml, buildHoTHtml, and buildSignatureBlock. Then add the following three routes. Place all three immediately before the existing router.get(’/:id/html’ route — this is important because the wildcard :id would otherwise catch these paths first.
Route 1: router.post(’/create-offline’ with requirePermission(‘canCreateOffers’) middleware and asyncHandler. Extract userId and userCompanyId from req.session and return 401 if either is missing. Parse req.body with zod expecting targetCompanyId as z.number(), documentType as z.enum([‘nda’, ‘offer_letter’, ‘heads_of_terms’]), dealModelId as z.number().optional(), and documentData as z.any().optional(). Call dealDocumentService.createDocument passing targetCompanyId, documentType, dealModelId, documentData, userCompanyId, and createdBy set to userId. Then immediately call db.update on dealDocuments setting deliveryMethod to the string ‘offline’ where id equals doc.id. Return res.status(201).json with the doc object spread and deliveryMethod: ‘offline’ added.
Route 2: router.get(’/:id/download-word’ as asyncHandler with no permission middleware — just session auth. Extract userCompanyId from session and return 401 if missing. Parse id from req.params as integer and return 400 if NaN. Call dealDocumentService.getDocumentById(id) and return 404 if the document is not found or if doc.userCompanyId does not match the session userCompanyId. Return 404 if doc.documentData is falsy. Cast doc.documentData as any into a variable called data. Determine bodyHtml by calling buildNdaHtml(data) if documentType is nda, buildOfferLetterHtml(data) if offer_letter, buildHoTHtml(data) if heads_of_terms, or return 400 for any other type. Append buildPhysicalSignatureBlock(doc.documentType, data, doc.id) to bodyHtml. Dynamically import html-to-docx using const HTMLtoDOCX = (await import(‘html-to-docx’)).default and call it with bodyHtml as the first argument, null as the second, and an options object as the third: { table: { row: { cantSplit: true } }, footer: false, pageNumber: false }. Build a filename using a docTypeNames map where nda maps to NDA, offer_letter to Offer_Letter, and heads_of_terms to Heads_of_Terms. Get sellerName from data?.sellerCompanyName with a fallback of Document and replace all spaces with underscores. The filename should be docTypeName_sellerName_Offline.docx. Set the Content-Type header to application/vnd.openxmlformats-officedocument.wordprocessingml.document, set Content-Disposition to attachment; filename= the filename in quotes, and send the buffer with res.send.
Route 3: router.post(’/:id/manual-status’ with requirePermission(‘canCreateOffers’) and asyncHandler. Extract userCompanyId from session and return 401 if missing. Parse id from params as integer and return 400 if NaN. Call dealDocumentService.getDocumentById(id) and return 404 if not found or if userCompanyId does not match. Parse req.body with zod expecting status as z.enum([‘sent’, ‘accepted’, ‘rejected’, ‘countered’]), notes as z.string().optional(), and confirmedAt as z.string().optional(). Parse confirmedAt into a Date if provided otherwise use new Date() as the confirmedDate. Call db.update on dealDocuments where id equals the document id, setting status to the parsed status, notes to the parsed notes or null, and if status equals ‘accepted’ also set respondedAt to confirmedDate. Fetch the updated document again using dealDocumentService.getDocumentById(id) and return it wrapped in sendSuccess(res, updated).
After all three routes are added confirm: router.post(’/create-offline’) exists, router.get(’/:id/download-word’) exists, router.post(’/:id/manual-status’) exists, all three appear before the /:id/html route in the file, buildPhysicalSignatureBlock is in the import from document-html-builders, TS error count remains at 6, and only deal-document.routes.ts was modified.​​​​​​​​​​​​​​​​
