Task 3 — UpgradePrompt component:
Create client/src/components/billing/UpgradePrompt.tsx:
A reusable component with this interface:
typescriptinterface UpgradePromptProps {
  feature: keyof TierFeatures;
  requiredPlan: PlanKey;
  title: string;
  description: string;
  children?: React.ReactNode; // optional preview content shown behind a blur
}
The component renders:

If useHasFeature(feature) returns true — render children normally (no gate)
If false — render a card with a lock icon (use lucide-react Lock icon), the title, the description, the required plan as a badge (e.g. "Requires Professional"), and a CTA button "Upgrade Plan" that links to /billing (the billing management page, which we will build later)
If null (loading) — render a skeleton placeholder matching the card dimensions
If children is provided and the feature is locked, render the children behind a blur-sm overlay with the lock card on top — this gives users a preview of what they would get

Style using Tailwind and shadcn/ui Card, Badge, Button, Skeleton components. Keep the design consistent with the existing app style — check a few existing components for the colour token conventions (text-foreground, bg-card, etc.).
Task 4 — FeatureGate component:
Create client/src/components/billing/FeatureGate.tsx:
Simpler inline gate for hiding/showing UI elements (buttons, menu items, tabs):
typescriptinterface FeatureGateProps {
  feature: keyof TierFeatures;
  children: React.ReactNode;
  fallback?: React.ReactNode; // optional — what to show if gated. Defaults to null.
}
If feature is available, renders children. If not, renders fallback or nothing. No loading state needed — just return null while loading.
