The DATABASE_URL is available via the existing config — use config.databaseUrl or however it is accessed in the codebase
Output file: /tmp/backup-{YYYY-MM-DD}.sql.gz — use a dated filename

Task 3 — Funnel instrumentation:
Create server/services/funnel.service.ts that records key funnel events to a new funnelEvents table. This is lightweight server-side instrumentation — no third-party analytics, no client-side tracking.
First, add a funnelEvents table to shared/schema/dashboard.ts:

id serial PK
userCompanyId integer FK → user_companies.id NOT NULL
userId integer FK → users.id, nullable
event varchar(100) NOT NULL — the event name
properties jsonb, nullable — any additional data
createdAt timestamp defaultNow NOT NULL

Run db:push after adding the table.
The funnel service should export a single track(userCompanyId: number, userId: number | null, event: string, properties?: Record<string, unknown>): void function — fire-and-forget, never throws, always catches and logs errors silently.
Hook track calls into the following server-side events — find the correct service or route handler for each and add the call fire-and-forget:

user.registered — in auth registration handler, properties: { sector: string }
trial.started — in billingService.createTrialSubscription, properties: { planKey, trialDays }
target.created — in target companies service/route when a new target is created, properties: { sector }
document.uploaded — in document upload handler, properties: { documentType, fileSize }
analysis.triggered — in expert analysis service when pipeline is triggered, properties: { targetCompanyId }
analysis.completed — in expert analysis service when synthesis completes, properties: { targetCompanyId, durationMs }
deal_model.saved — in deal model service when a model is saved, properties: { hasMultipleFundingLines: boolean }
document.generated — in deal document service when an offer/HoT is generated, properties: { documentType }
subscription.activated — in billingService.activateSubscription, properties: { planKey, billingInterval }
onboarding.completed — in the onboarding complete endpoint, properties: {}
