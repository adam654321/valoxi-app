Step 10 — End-to-End API Verification
Please test the Deal Modeller API by doing the following. Report the results of each step — what was returned, any errors, and whether the data looks correct.
First, find a testable company:

Query the database to find a target company that has completed expert analysis results. We need one with at least QoE and Valuation expert types with status = 'completed'. Run a SQL query or use Drizzle to find one:

sqlSELECT DISTINCT ear.target_company_id, tc.company_name, ear.expert_type, ear.status
FROM expert_analysis_results ear
JOIN target_companies tc ON tc.id = ear.target_company_id
WHERE ear.status = 'completed'
ORDER BY ear.target_company_id;
Also check if that company has financial data (income statements, balance sheets). Report which company ID we can use and what expert results and financial data it has.

Check if there's a valid user session we can use for testing. We need a userId and userCompanyId. If there's no easy way to test via the API with auth, create a temporary test script or debug endpoint that bypasses session auth for this verification only.

Then test the API flow:

Create a deal model — POST /api/v2/deal-models/create/:companyId for the company found above. Report:

Did it succeed?
How many adjustments were created? Are they all status: 'suggested'?
How many funding lines were created? What types?
Were the valuation parameters populated from the expert data (multiple, multipleLow, multipleHigh)?
Were the consideration fields populated from the deal structure expert?
Are the calculated fields populated (enterpriseValue, offerPrice, totalFees, totalFundingRequired)?
Are the snapshots populated?


Get the model — GET /api/v2/deal-models/:id with the ID from step 3. Confirm it returns the model with adjustments and funding lines.
Accept some adjustments — PUT /api/v2/deal-models/:id/adjustments/bulk — accept the first 3 suggested adjustments. Report whether the model's calculated values changed after recalculation.
Activate a funding line — PUT /api/v2/deal-models/:id/funding-lines/:lineId — set isActive: true and amountUsed to some value on one of the seeded lines (e.g. receivables finance). Report whether funding stack calculations updated.
Duplicate the model — POST /api/v2/deal-models/:id/duplicate. Confirm:

New model created with incremented version
parentModelId links to original
Adjustments and funding lines were copied
Status is 'draft'


Lock the original — POST /api/v2/deal-models/:id/lock. Then try to update it — PUT /api/v2/deal-models/:id with any change. Confirm it returns an error because the model is locked.

Report a summary of:
