We are continuing to build the billing layer. Stage 1, Step 5: the subscription enforcement middleware — the server-side gate that blocks access to premium endpoints based on subscription status and tier. This is the most critical piece of the billing system. UI hiding alone is never sufficient; this is the server-side enforcement layer.
Context:

server/services/billing.service.ts exports billingService with getSubscription and getEntitlements
shared/entitlements.ts exports hasFeature and the TierFeatures type
shared/schema/billing.ts exports PlanKey and SubscriptionStatus
Existing middleware lives in server/middleware/. Look at server/middleware/auth.ts for the pattern — it reads from req.session.userId and calls next() or returns a 401/403. Follow the same pattern.
The authenticated user's userCompanyId is available via req.session — check the existing auth middleware and session setup to confirm the exact field name used, and use the same one.
All API routes are under /api/v2/

What to build:
Create server/middleware/subscription.ts exporting the following middleware functions:
requireActiveSubscription
Checks that the tenant has a subscription with status active, trialing, or admin_comped. If the subscription is missing, canceled, incomplete, or past_due, return HTTP 402 with JSON body { error: 'subscription_required', message: 'An active subscription is required to access this feature.' }. If the session has no userCompanyId, return 401. Attach the subscription to req.subscription for downstream use (avoids a second DB hit in the route handler).
requireFeature(feature: keyof TierFeatures)
Returns a middleware function. First runs the same active subscription check as requireActiveSubscription. Then calls hasFeature(subscription.planKey, feature). If the feature is not available on the tenant's plan, return HTTP 403 with JSON body { error: 'feature_not_available', message: 'This feature is not available on your current plan.', requiredUpgrade: true }. If the check passes, call next().
requirePlan(...plans: PlanKey[])
Returns a middleware function. Checks the tenant's planKey is one of the provided values. Returns 403 with { error: 'plan_required', message: 'This feature requires a higher plan.', requiredUpgrade: true } if not. Useful for routes that need a specific minimum tier (e.g. requirePlan('PROFESSIONAL', 'EXPERT', 'ENTERPRISE')).
TypeScript: extend Express's Request interface to include subscription?: Subscription so TypeScript does not complain about req.subscription in route handlers. Add this augmentation in the same file using declare global { namespace Express { interface Request { subscription?: Subscription } } }.
All three exports must work as Express middleware (correct (req, res, next) signature or factory returning that signature).
Do not apply this middleware to any routes yet — that comes in a later step.
