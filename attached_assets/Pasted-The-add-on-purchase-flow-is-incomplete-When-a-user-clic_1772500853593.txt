The add-on purchase flow is incomplete. When a user clicks "Purchase" for additional company slots or seats, the API returns a clientSecret but the frontend does nothing with it — there's no Stripe Elements payment step, so the payment never completes and nothing is recorded.
We need to replace the current Payment Intent approach with a simpler Subscription Item approach instead. Since the user already has an active Stripe subscription, we can just add the add-on as an additional subscription item on their existing subscription — no separate payment intent needed, it gets billed on their next invoice automatically.
Read these files first before making any changes:

server/routes/billing.routes.ts — the POST /addon endpoint
server/services/billing.service.ts — purchaseAddonSlots method
shared/schema/billing.ts — subscriptions table structure

Fix 1 — Change POST /api/v2/billing/addon to use subscription items:
Replace the Payment Intent approach with this flow:

Retrieve the user's current subscription from the DB to get stripeSubscriptionId
If stripeSubscriptionId is null or empty (e.g. admin_comped), skip Stripe and just update the DB count directly
If stripeSubscriptionId exists, call stripe.subscriptionItems.create({ subscription: stripeSubscriptionId, price: lookupKey, quantity: requestedQuantity }) using the correct lookup key (ma_addon_company_slot or ma_addon_seat)
After successful Stripe call, update addOnCompanySlots or additionalSeats on the subscription row by incrementing by the requested quantity
Log a subscription event: addon.company_slot_added or addon.seat_added
Return { success: true, addedQuantity, newTotal }
Remove the clientSecret return entirely — it's no longer needed

Fix 2 — Fix POST /api/v2/billing/remove-seat similarly:
Same pattern — if stripeSubscriptionId exists, find the subscription item for ma_addon_seat via stripe.subscriptionItems.list({ subscription: stripeSubscriptionId }), then call stripe.subscriptionItems.update(itemId, { quantity: newQuantity }) or delete it if quantity reaches 0. Update DB accordingly.
Fix 3 — Frontend cleanup:
In client/src/pages/billing.tsx, remove any code that was handling clientSecret from the add-on purchase response. On successful purchase response { success: true }, just invalidate the subscription query so the seat/slot counts refresh, and show a success toast: "Add-on activated — your next invoice will include the additional charge."
Fix 4 — Quantity selector for company slots:
Currently the company slots selector goes up to some default. Make sure the quantity selector allows 1–10 additional slots and shows the running total cost: e.g. "3 slots — £27/month".
