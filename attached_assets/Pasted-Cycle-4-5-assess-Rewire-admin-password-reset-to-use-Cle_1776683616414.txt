PROPOSED CHANGE SUMMARY
Replace the current admin password reset (which writes to users.password_hash via bcrypt and clears Valoxi sessions) with a Clerk-based flow. The admin clicks a single button. The backend looks up the user's clerkUserId, calls Clerk's signInTokens API to create a one-time sign-in token, emails the user a sign-in link carrying that token, and returns a confirmation to the admin. No password is typed anywhere.
New flow diagram:
Admin UI → POST /api/v2/admin/users/:id/reset-password (no body or empty body)
→ Look up user, get clerkUserId
→ If no clerkUserId, return 400 with message "User has not set up Clerk access yet"
→ Else, clerkClient.signInTokens.createSignInToken({ userId: clerkUserId, expiresInSeconds: 86400 })
→ Construct sign-in URL using the token
→ emailApiService sends email with the URL
→ Return { success: true, message: "Sign-in link sent to <email>" }
Admin UI changes: remove password input field, replace with a single "Send sign-in link" button, update success/error messaging.
Dead code: passwordResetService.adminResetPassword can be left in place but becomes unused. Out of scope to delete in this cycle (leave for post-Phase-5 cleanup sweep).
