Replit Prompt 2: Fix CSRF Token on DD Document Link/Unlink
## Context

The Stage 2 Due Diligence document linking feature is broken because two functions in `client/src/components/target-company/DueDiligenceTab.tsx` use raw `fetch()` calls instead of the `apiRequest` helper. The due-diligence API routes are protected by CSRF middleware (`validateCsrfToken`), and `apiRequest` from `@/lib/queryClient` automatically attaches the `x-csrf-token` header on non-GET requests. The raw `fetch()` calls don't include this header, so every link/unlink request is silently rejected with a 403.

## Task

Check that `apiRequest` is imported from `@/lib/queryClient`. If it's already imported (e.g. `queryClient` is imported from there), just add `apiRequest` to the existing import. If not, add the import.

### 2. Fix `handleLinkDoc` (around line 378)

Replace the raw `fetch()` call with `apiRequest`. The current code will look something like:

```typescript
const res = await fetch(`/api/v2/due-diligence/company/${targetCompanyId}/requirement/${requirementId}/documents`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },

await apiRequest('POST', `/api/v2/due-diligence/company/${targetCompanyId}/requirement/${requirementId}/documents`, { documentId, notes });

Note: apiRequest throws on non-OK responses, so the existing try/catch error handling should still work. Adjust if necessary — remove any manual res.ok checking since apiRequest handles that by throwing.
