Step 1. Extend server/routes/webhooks.routes.ts with three event handlers.
After signature verification passes, dispatch on evt.type:
case 'user.created':
Read primary email from the Clerk payload. The Clerk user object has evt.data.primary_email_address_id (string) and evt.data.email_addresses (array of { id, email_address, ... }). Find the entry whose id matches primary_email_address_id and use its email_address.
Look up users by email (case-insensitive via LOWER() or sql template with lower()).
If no match found: log "[clerk-webhook] user.created: no matching user for <email> (Clerk id: <clerkUserId>) — awaiting invitation flow" and return 200.
If match found but isActive is false: log conflict and return 200 without linking (defensive — inactive accounts should not be silently reactivated by a Clerk sign-up).
If match found, isActive is true, clerk_user_id is null: UPDATE users SET clerk_user_id = <clerkUserId> WHERE id = <matched_id>. Log "[clerk-webhook] user.created: linked user <id> (<email>) to Clerk <clerkUserId>".
If match found, isActive is true, clerk_user_id equals incoming Clerk id: no-op idempotent. Log "[clerk-webhook] user.created: user <id> already linked, skipping".
If match found, isActive is true, clerk_user_id is a different Clerk id than incoming: log "[clerk-webhook] user.created: CONFLICT — user <id> already linked to Clerk <existingId>, incoming <newId> — skipping". Do not overwrite. Return 200 (so Clerk doesn't retry).
case 'user.updated':
Read first_name and last_name from evt.data.
Look up users by clerk_user_id = evt.data.id.
If found: UPDATE firstName and lastName if either changed. Log "[clerk-webhook] user.updated: synced user <id>".
If not found: log "[clerk-webhook] user.updated: no user linked to Clerk <clerkUserId>" and return 200. This happens for a Clerk user that signed up but is awaiting 4D invitation metadata.
case 'user.deleted':
Clerk's delete payload has evt.data.id and evt.data.deleted (boolean). Read evt.data.id.
Look up users by clerk_user_id = evt.data.id.
If found: UPDATE isActive = false. Log "[clerk-webhook] user.deleted: soft-deleted user <id>".
If not found: log "[clerk-webhook] user.deleted: no user linked to Clerk <clerkUserId>" and return 200.
default:
Log "[clerk-webhook] received unexpected event type <type>" and return 200. Clerk shouldn't send events we didn't subscribe to, but be defensive.
All handlers return 200 with { received: true } (matching existing pattern) to prevent Clerk retries.
